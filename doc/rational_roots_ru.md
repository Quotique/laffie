## Поиск рациональных корней многочлена

### Математическая основа

Теорема о рациональных корнях: если моническый многочлен с целыми коэффициентами
`x^n + ... + d == 0` имеет рациональный корень, то он является делителем свободного члена `d`.

Для немонического случая `a * x^n + ... + d == 0` рациональные корни имеют вид `p/q`,
где `p` делит `d`, а `q` делит `a`.

### Алгоритм

1. Получить делители свободного члена (включая отрицательные).
2. Подставить каждый кандидат в многочлен.
3. Если подстановка даёт 0 — это корень, делим многочлен на `(x - u)` и продолжаем
   с многочленом меньшей степени.

### Запись в виде правила

#### Вариант 1: фиксированная степень, явные коэффициенты

Для кубического уравнения разделённый многочлен выписывается вручную через схему Горнера:

```
rule {
    attr level(5), goal(find(x)), one(a);

    a * x^3 + b * x^2 + c * x + d == 0 =>
        (x == u) || (a * x^2 + (b + a*u) * x + (c + u*(b + a*u)) == 0);

    a != 0,
    d != 0,
    u in divisors(d),
    substitute(a*x^3 + b*x^2 + c*x + d, x, u) == 0;
}
```

Аналогичные правила записываются для четвёртой и более высоких степеней.

#### Вариант 2: обобщённое правило (степень-агностичное)

```
rule {
    attr level(5), goal(find(x));

    F == 0 =>
        (x == u) || (Q == 0);

    F is_polynomial(x),
    d = free_term(F, x),
    d != 0,
    u in divisors(d),
    substitute(F, x, u) == 0,
    Q = poly_div(F, x - u);
}
```

Требует более развитой инфраструктуры (см. раздел «Необходимые расширения»).

### Архитектура: OpenHypothesis и grounding

#### Проблема

Требование `u in divisors(d)` — не обычный предикат, а **генератор**: оно связывает
свободный параметр `u` со значениями из множества. Семантика `in` в требованиях
зависит от того, связан ли левый аргумент:

- **Связан** → ограничение (предикат): проверить принадлежность множеству.
- **Не связан** → генератор: перебрать элементы, связать параметр.

При нескольких свободных параметрах (например, `u in set(1,2,3), v in set(4,5,6),
u+v == 7`) возникает совместная система ограничений.

#### Решение: OpenHypothesis → grounding через find

Вводятся два вида гипотез:

- **OpenHypothesis** — гипотеза, содержащая свободные (несвязанные) параметры и
  ограничения на них. Представляет **семейство** конкретных гипотез.
- **Hypothesis** (ground) — все параметры связаны, можно проверять требования.

Поток обработки:

```
Rule::apply()
  → Hypothesis
      содержит: resolution, params (связанные), free_params (свободные),
                requirements (включая ограничения на свободные)

Hypothesis::ground()
  → если free_params пуст — тривиальная конвертация
  → иначе: формирует подзадачу find(free_params)
    с requirements, содержащими свободные параметры, как условиями
  → солвер возвращает множество решений (подстановок)
  → для каждого решения: подставляет значения в resolution и requirements
  → Vec<GroundedHypothesis>  (все параметры связаны)

Solver::try_prove_hypothesis(hypothesis)
  → как сейчас, без изменений
```

Если `apply()` вернул гипотезу без свободных параметров — она уже ground,
шаг `ground()` пропускается. Обратная совместимость бесплатная.

#### Терминология

| Понятие | Название | Термин в литературе |
|---------|----------|---------------------|
| Гипотеза (общий случай, может содержать свободные параметры) | `Hypothesis` | non-ground clause [1, 2] |
| Конкретизированная гипотеза (все параметры связаны) | `GroundedHypothesis` | ground instance [1, 2] |
| Конкретизация (превращение Hypothesis → GroundedHypothesis) | grounding | instantiation / grounding / означивание [3, 4] |
| Свободные параметры | `free_params` | free variables / свободные переменные [4, 5] |

#### Почему find, а не специальный перебор

1. **Не нужна новая механика** — солвер уже умеет решать `find` с ограничениями.
2. **Масштабируется** — один генератор, несколько, constraint propagation —
   всё это задача солвера, и улучшения в нём автоматически распространяются.
3. **Архитектурно чисто** — `apply()` остаётся чистой операцией над термами,
   `try_prove_hypothesis()` не усложняется. Новая логика локализована в `ground()`.

#### Множественные решения

Подзадача `find` может вернуть несколько решений (например, несколько делителей
являются корнями). Каждое решение порождает отдельную ground-гипотезу. Это согласуется
с текущей архитектурой, где `apply()` уже возвращает `Vec<Hypothesis>` (множественные
гипотезы от ассоциативно-коммутативного паттерн-матчинга), и солвер рассматривает их все.

### Необходимые расширения синтаксиса и системы

#### 1. `divisors(n)` — множество делителей целого числа

Встроенная функция, возвращающая множество всех целых делителей числа `n`
(положительных и отрицательных). Аналог уже существующего `sqrt()`.

Для немонического случая потребуется `rational_divisors(d, a)`, возвращающая
множество `p/q`, где `p | d`, `q | a`.

#### 2. `in` в секции требований — семантика зависит от контекста

Парсер уже поддерживает `in` как предикат. Изменения нужны только в солвере:

- **Связанный аргумент** → обычный предикат, нормализатор `in` вычисляет
  `true`/`false` при конкретных аргументах.
- **Несвязанный аргумент** → попадает в `free_params` и `constraints`
  при создании `OpenHypothesis`, разрешается через `find`.

#### 3. `substitute(expr, var, value)` — подстановка и вычисление

Принимает терм, заменяет все вхождения переменной на значение и вычисляет результат.
Альтернативные варианты синтаксиса:

- `replace(F, x = u)` — как в закомментированном правиле в `power.sym`
- `substitute(expr, x, u)` — более явная форма
- `eval(F, x => u)` — с лямбда-нотацией

#### 4. `poly_div(F, x - u)` — полиномиальное деление (для варианта 2)

Возвращает частное от деления многочлена `F` на `(x - u)`. Необходимо только для
обобщённого правила. В варианте 1 деление выполняется «вручную» через коэффициенты
схемы Горнера.

#### 5. `is_polynomial(x)`, `free_term(F, x)` — анализ структуры (для варианта 2)

- `is_polynomial(x)` — проверка, что терм является многочленом относительно `x`.
- `free_term(F, x)` — извлечение свободного члена многочлена.

### Порядок реализации

**Этап 1** — минимальный набор для правил с фиксированной степенью:

1. `OpenHypothesis` с `free_params` — структура данных.
2. `Solver::ground()` — формирование подзадачи `find` и создание ground-гипотез.
3. `divisors(n)` — нормализатор, раскрывающий в `set(...)`.
4. Нормализатор `in` для конкретных аргументов (`3 in set(1,2,3)` → `true`).
5. `substitute(expr, var, value)` — встроенная функция подстановки.

**Этап 2** — обобщённые правила:

6. `poly_div`, `is_polynomial`, `free_term`.
