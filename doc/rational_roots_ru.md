## Поиск рациональных корней многочлена

### Математическая основа

Теорема о рациональных корнях: если моническый многочлен с целыми коэффициентами
`x^n + ... + d == 0` имеет рациональный корень, то он является делителем свободного члена `d`.

Для немонического случая `a * x^n + ... + d == 0` рациональные корни имеют вид `p/q`,
где `p` делит `d`, а `q` делит `a`.

### Алгоритм

1. Получить делители свободного члена (включая отрицательные).
2. Подставить каждый кандидат в многочлен.
3. Если подстановка даёт 0 — это корень, делим многочлен на `(x - u)` и продолжаем
   с многочленом меньшей степени.

### Реализованное

#### Вариант 1: фиксированная степень (работает)

Кубическое правило в `symbols/power.sym`:

```
rule {
    attr level(5),goal(find(x)),one(b),one(c),zero(b),zero(c);

    x^3 + b * x^2 + c * x + d == 0 =>
        (x == u) || (x^2 + (b + u) * x + (c + u*(b + u)) == 0);

    d != 0,
    u in divisors(d),
    substitute(x == u, x^3 + b * x^2 + c * x + d) == 0;
}
```

Разделённый многочлен выписан вручную через схему Горнера. Аналогичные правила
можно записать для четвёртой и более высоких степеней.

#### Инфраструктура

1. **`Hypothesis` / `GroundedHypothesis`** (`solver/rule/hypothesis.rs`)
   — `Hypothesis` содержит `free_params` (свободные параметры) и `requirements`.
   Метод `ground()` извлекает `<param> in set(...)` генераторы из requirements,
   строит cartesian product всех комбинаций, подставляет значения →
   `Vec<GroundedHypothesis>`.

2. **`divisors(n)`** (`symbols/divisors.sym`)
   — Python-калькулятор, возвращает `set(...)` всех целых делителей числа `n`
   (положительных и отрицательных).

3. **`in` предикат** (`solver/term/symbol/base/op_in.rs`)
   — truth checker: `a in set(...)` → `true`/`false`/`unknown`.
   В requirements с несвязанным левым аргументом работает как генератор
   (через `extract_generators()` в `ground()`).

4. **`substitute(x == val, expr)`** (`solver/term/symbol/base/substitute.rs`)
   — подставляет значение переменной в выражение и нормализует результат.

5. **`is_polynomial(F, x)`** (`symbols/is_polynomial.sym`)
   — SymPy-калькулятор, проверяет, что `F` — многочлен по `x`.

6. **`free_term(F, x)`** (`symbols/free_term.sym`)
   — SymPy-калькулятор, извлекает свободный член многочлена.

7. **`poly_div(F, divisor)`** (`symbols/poly_div.sym`)
   — SymPy-калькулятор, полиномиальное деление.

8. **Общий конвертер Term ↔ SymPy** (`symbols/py/sympy_convert.py`)
   — `to_sympy()` / `from_sympy()` для Python-калькуляторов.

### Архитектура: Hypothesis и grounding

#### Проблема

Требование `u in divisors(d)` — не обычный предикат, а **генератор**: оно связывает
свободный параметр `u` со значениями из множества. Семантика `in` в требованиях
зависит от того, связан ли левый аргумент:

- **Связан** → ограничение (предикат): проверить принадлежность множеству.
- **Не связан** → генератор: перебрать элементы, связать параметр.

При нескольких свободных параметрах (например, `u in set(1,2,3), v in set(4,5,6),
u+v == 7`) возникает совместная система ограничений.

#### Решение: grounding через find-подзадачу

Два вида гипотез:

- **Hypothesis** — может содержать свободные (несвязанные) параметры и
  ограничения на них. Представляет **семейство** конкретных гипотез.
- **GroundedHypothesis** — все параметры связаны, можно проверять требования.

Текущая реализация grounding — через cartesian product генераторов `<param> in set(...)`.
Если генераторов нет, `ground()` возвращает пустой результат (TODO: делегировать
в find-подзадачу).

Целевой поток обработки:

```
Rule::apply()
  → Hypothesis { resolution, params, free_params, requirements }

Hypothesis::ground()
  → если free_params пуст — тривиальная конвертация
  → иначе: формирует подзадачу find(free_params)
    с requirements как условиями (givens)
  → солвер возвращает множество решений (подстановок)
  → для каждого решения: подставить значения → GroundedHypothesis

Solver::try_prove_hypothesis(grounded_hypothesis)
  → как сейчас, без изменений
```

#### Почему find, а не специальный перебор

1. **Не нужна новая механика** — солвер уже умеет решать `find` с ограничениями.
2. **Масштабируется** — один генератор, несколько, constraint propagation —
   всё это задача солвера, и улучшения в нём автоматически распространяются.
3. **Архитектурно чисто** — `apply()` остаётся чистой операцией над термами,
   `try_prove_hypothesis()` не усложняется. Новая логика локализована в `ground()`.

#### Множественные решения

Подзадача `find` может вернуть несколько решений (например, несколько делителей
являются корнями). Каждое решение порождает отдельную ground-гипотезу. Это согласуется
с текущей архитектурой, где `apply()` уже возвращает `Vec<Hypothesis>` (множественные
гипотезы от ассоциативно-коммутативного паттерн-матчинга), и солвер рассматривает их все.

#### Терминология

| Понятие | Название | Термин в литературе |
|---------|----------|---------------------|
| Гипотеза (общий случай, может содержать свободные параметры) | `Hypothesis` | non-ground clause [1, 2] |
| Конкретизированная гипотеза (все параметры связаны) | `GroundedHypothesis` | ground instance [1, 2] |
| Конкретизация (превращение Hypothesis → GroundedHypothesis) | grounding | instantiation / grounding / означивание [3, 4] |
| Свободные параметры | `free_params` | free variables / свободные переменные [4, 5] |

### План: обобщённое правило (вариант 2)

#### Целевое правило

```
rule {
    attr level(5), goal(find(x, ..));

    F == 0 =>
        (x == u) || (Q == 0);

    is_polynomial(F, x),
    free_term(F, x) == d,
    d != 0,
    u in divisors(d),
    substitute(F, x, u) == 0,
    poly_div(F, x - u) == Q;
}
```

Новый синтаксис не нужен: `==` с несвязанным параметром в одной из сторон
интерпретируется как связывание через find-подзадачу (`free_term(F, x) == d`
нормализуется в `6 == d`, солвер связывает `d`).

#### Подзадача 1: FindGoal и парсинг multi-var find — ✅

- `src/solver/task/goal.rs` — `FindGoal { targets: Vec<TermBuf>, term: TermProps }`
- `Goal::Find(FindGoal)`, парсинг `find(x, y, ...)` извлекает все аргументы
- `find` помечен как коммутативный символ (`container.rs`)

#### Подзадача 2: Обнаружение ответа multi-var find — ✅

- `src/solver/task/solution.rs` — `find_bindings: HashMap<TermBuf, TermIdx>`
- `check_find_answer` с `match_term!` — инкрементально связывает targets,
  собирает конъюнкцию `&&` когда все bound
- Коммутативный матчинг с placeholder: `goal(find(x, ..))` в правилах
  матчит `find(x)`, `find(x, y)` и т.д.
- `args_permutations()` для коммутативных символов, пустой arglist в placeholder
- Правила с `answer(...)` (`set.sym`, `logic_or.sym`) оставлены как `goal(find(x))`
  без `..` — `answer()` shortcut работает только для single-var find

**Валидация:** линейная система `find(x, y)` решается. 64 теста, 43 задачи.

#### Подзадача 3: GroundingResult и делегирование в солвер
