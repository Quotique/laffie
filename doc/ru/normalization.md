# Нормализация

**Нормализация** — синтаксическое приведение терма к канонической форме
с гарантией сохранения семантики. Цель — сократить количество
вариантов, в которых может быть представлено одно и то же выражение,
чтобы шаги матча с шаблонами правил и проверки на дубликаты
становились простыми синтаксическими сравнениями.

Без нормализации `2 + x` и `x + 2` рассматривались бы системой как
разные термы; правило с шаблоном `a + b ⇒ …` приходилось бы пробовать
во всех порядках аргументов; повторное применение правил порождало бы
бесконечные цепочки эквивалентных переписываний.

## Нормализация и упрощение

Нормализация и упрощение — разные понятия.

| Свойство | Нормализация | Упрощение (`Transform`-подзадача) |
|----------|--------------|------------------------------------|
| Где реализуется | В ядре (`TermMut::normalize`). | Через правила, написанные на языке системы. |
| Гарантия сохранения семантики | Безусловная. | Обеспечивается корректностью введённых правил. |
| Когда выполняется | Автоматически, при создании каждого нового терма (после применения правила). | Явно — для активного терма на шаге упрощения цикла. |
| Возможность отключить | Да, через `normalize(<level>)` в правиле. | Не требует отключения. |
| Изменяется обучением | Нет, требует изменений ядра. | Да: добавление новых упрощающих правил расширяет класс упрощений. |

Поэтому раскрытие скобок по формуле или вычисление производной — это
**упрощение** (нужны правила); вычисление `2 + 3 → 5` или
`3 + x → x + 3` — это **нормализация**.

## Что делает нормализация

`TermMut::normalize` рекурсивно проходит дерево, на каждом узле выполняя:

1. **Раскрытие вложенности ассоциативных операций.** Вложенные
   одноимённые ассоциативные операции «склеиваются» в одну с большим
   числом аргументов: `(x + y) + z → +(x, y, z)`.
2. **Калькулятор символа.** Для функционального символа узла
   вызывается его процедура (`SymbolProgram::calculator`), которой
   передаётся текущий уровень нормализации. Поведение зависит от
   символа и уровня — см. ниже.
3. **Упорядочивание коммутативных аргументов.** Для коммутативных
   символов (например, `+`, `*`, `==`) аргументы сортируются по
   стабильному порядку, заданному `SymbolProgram::arg_cmp`.

## Уровни нормализации

Уровень нормализации — натуральное число (тип `NormalizationLevel`).
Каждый уровень включает операции предыдущих:

| Уровень | Что добавляет |
|---------|--------------|
| 0 | Только раскрытие вложенности ассоциативных операций. Калькуляторы и сортировка не вызываются. |
| 1 | + сортировка коммутативных аргументов. + калькуляторы устраняют тривиальные операции (вычитание / прибавление нуля, умножение / деление на единицу, удаление лишних обёрток). |
| 2 | + арифметические вычисления с константами (`2 + 3 → 5`). |
| 3 (включая `max`) | + приведение подобных (`x + 2x → 3x`), сворачивание степеней (`x · x → x²`). |

Все уровни выше третьего ведут себя как третий — структура `NormalizationLevel(u64)`
позволяет хранить любое неотрицательное число; в текущей реализации
третий уровень — потолок различимого поведения.

Реализация ступеней:

- Сортировку и раскрытие ассоциативной вложенности делает
  `TermMut::normalize` (`src/solver/term/refer_mut.rs`).
- Все остальные операции лежат в калькуляторах символов
  (`src/solver/term/symbol/base/*.rs`): для каждого символа
  калькулятор внутри `match level { NormalizationLevel(0) => …,
  NormalizationLevel(1) => …, NormalizationLevel(2) => …, _ => … }`
  определяет, что именно он делает.

## Когда используется какой уровень

По умолчанию ядро применяет максимальный уровень
(`NormalizationLevel::max()`) — это даёт наиболее полное приведение к
канонической форме. Места, где это происходит явно:

- При создании любого нового терма из применения правила
  (`Solver::produce` через `Hypothesis::ground` нормализует требования
  максимально).
- При вычислении подзадачей `Prove` цели на тривиальную истину
  (`Solver::prove`).
- При построении ответов и в ряде вспомогательных мест.

В правилах через атрибут `normalize(<level>)` можно понизить уровень
нормализации **результата** применения правила — это нужно, когда
правилу важно сохранить терм в неканонической форме, чтобы его смогло
подхватить другое правило.

## Когда нормализация мешает

Пример из правила, понижающего степень суммы методом отделения
множителя:

```
rule {
   attr replace, level(4), goal(transform(x)), normalize(2);

   (a+b)^n <=> (a+b)^(n - 1)*(a + b);

   a is known,
   b is known;
}
```

После применения этого правила в результате присутствует пара
сомножителей `(a + b)^(n - 1) * (a + b)`. На уровне нормализации 3
сюда сработало бы сворачивание степеней — пара одинаковых выражений
снова склеилась бы в `(a + b)^n`, а правило потеряло бы смысл
(результат совпал бы с входом). Атрибут `normalize(2)` ограничивает
нормализацию вторым уровнем, оставляя произведение нераскрытым до
тех пор, пока другое правило (раскрывающее скобки в умножении) не
применится первым.

## Пример

Терм `(4x + 7) - (2x + 1) = 0`, нормализация максимального уровня:

1. Раскрытие вложенности ассоциативных операций (минус как
   ассоциированное прибавление противоположных):
   `+(4·x, 7, -1·2·x, -1·1) == 0`.
2. Калькуляторы уровня 2 — арифметика констант:
   `+(4·x, 7, -2·x, -1) == 0`.
3. Калькуляторы уровня 3 — приведение подобных:
   `+((4-2)·x, (7-1)) == 0`.
4. Калькуляторы уровня 2 — арифметика констант (повторно):
   `+(2·x, 6) == 0`.
5. Итоговый нормализованный терм: `2x + 6 == 0`.

## Где это в коде

| Что | Файл / тип |
|------|-----------|
| Тип уровня | `NormalizationLevel` (`src/solver/lib.rs`) |
| Точка входа | `TermMut::normalize` (`src/solver/term/refer_mut.rs`) |
| Раскрытие ассоциативной вложенности | `TermMut::associative_nesting_remove` (там же) |
| Сортировка коммутативных | `TermMut::commutative_reorder` (там же) |
| Калькуляторы символов | `src/solver/term/symbol/base/*.rs` (`plus.rs`, `mul.rs`, `divide.rs`, `power.rs`, …) |
| Атрибут `normalize` правила | `src/solver/rule/rule_attribute.rs` (`RuleAttr::Normalize`) |
