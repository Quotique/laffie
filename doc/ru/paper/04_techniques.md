## 4. Семейство логических приёмов

В двенадцати верифицированных карточках каталога (§5) «логический шаг»
гибридной схемы — не один трюк, а семейство приёмов, систематизируемое
по стадии применения относительно делегирования: **предобработка**
(логический слой переписывает задачу до делегирования),
**разбор случаев** (логический слой ветвит задачу на подзадачи с
фиксированным значением или знаком ключевого выражения) и
**постпроцессинг** (логический слой фильтрует или интерпретирует
ответ калькулятора). Сборка ветвей — дизъюнктивная резолюция из §3.2 —
общий финальный шаг, отдельно не выделяется. Приёмы внутри одной
карточки часто комбинируются: факторизация → разбор случаев по
обнулению множителей; формальное решение → ОДЗ-фильтр.

Каждый приём ниже описывается через четвёрку: определение, привязка
к строительным блокам §3.2, эталонная карточка, поведение чистого
SymPy.

### 4.1. Предобработка

**Факторизация выражения.** Преобразование выражения в произведение,
открывающее перспективу разбора случаев по обнулению множителей. Реализация:
рерайт через правило преобразования с последующей дизъюнктивной
резолюцией при переходе `a · b == 0 ⇒ (a == 0) || (b == 0)`. Эталонные
карточки: C2 (`a² − 1 = (a − 1)(a + 1)`), C24 (`a² − 4 = (a − 2)(a + 2)`),
C26 (`x⁴ − (a + 1)x² + a = (x² − 1)(x² − a)`). SymPy умеет факторизовать
через `factor()`, но не использует разложение для дальнейшего разбора
по случаям.

**Знак-разбор модулей.** Преобразование выражения с модулями в
кусочно-линейную форму через разбор по знакам подмодульных выражений.
Реализация: связывание по генератору по бинарному множеству знаков
для каждого подмодуля + дизъюнктивная резолюция. Эталонная карточка: C28
(`|x − 1| + |x + 1|` → кусочная функция). SymPy публичного API на
такой разбор не предоставляет; `Piecewise` строится только вручную.

**Асимптотическая редукция.** Замена выражения доминирующим членом при
предельном переходе, определяемая сравнением порядков роста. Реализация:
чистый рерайт без блоков делегирования — порядки роста выражаются
термовыми правилами. Эталонная карточка: C23
(`x · e^x − e^{2√(1 + x²)} ∼ −e^{2x}` при `x → +∞`). SymPy `limit`
вычисляет конкретные пределы корректно, но не делает символьного
сравнения порядков с параметром.

**Распознавание rank-дефицита.** Анализ системы линейных уравнений
на пропорциональность строк; при обнаружении — построение условия
согласованности правых частей. Реализация: связывание по генератору
по конечному множеству возможных значений ранга + дизъюнктивная
резолюция.
Эталонная карточка: C11 (`{x + y = 1, 2x + 2y = p}` → условие `p = 2`).
SymPy `linsolve` возвращает пустое множество без объяснения причины
несовместности.

### 4.2. Разбор случаев

Каноническая стадия применения паттерна, опирающаяся на дизъюнктивную
резолюцию из §3.2 поверх конкретизации. Конечный набор ветвей может
порождаться двумя способами: (i) связывание по генератору с
калькулятором-генератором, выдающим перечислимое множество (`u in
divisors(d)`); (ii) явное перечисление ветвей в дизъюнкции резолюции,
когда их число мало и известно заранее (`(a == 0 && …) || (a != 0
&& …)`). Оба варианта используют один и тот же механизм конкретизации
и ту же дизъюнктивную резолюцию; различие — в источнике перечисления
ветвей. Конкретный выбор иллюстрируется в §7 (явное перечисление в
правиле C1) и в §3.2 (генератор-цикл в rational_roots).

**По обнулению выражения.** Ветвление по тому, обнуляется ли в задаче
критическое выражение: коэффициент уравнения, множитель
факторизованного коэффициента, ведущий элемент гауссовой процедуры.
Конечное множество ветвей — бинарное `{== 0, != 0}`. Эталонные
карточки: C1 (коэффициент `a` в `a · x = a`; в реализации §7 ветви
перечислены явно), C24 (множители `a − 2`, `a + 2`), C2 (двухуровневый:
старший и линейный коэффициенты), C21 (ведущие элементы `ν`,
`λ + ν` в `rref` параметрической матрицы). SymPy в этих случаях делит на
параметр-содержащее выражение без явного отслеживания случая обнуления
и теряет вырожденную ветвь.

**По знаку выражения.** Ветвление по знаку: коэффициента (определяет,
разворачивается ли неравенство при делении), параметра под корнем
(определяет вещественность), показателя экспоненты (определяет
поведение в пределе). Конечное множество ветвей — тернарное
`{< 0, == 0, > 0}` или его подмножество. Эталонные карточки: C10
(знак `a` в `a · x > b`), C26 (знак `a` в `x² = a`), C23 (знак
показателя `2 − α`), C25 (знак `a` для направления параболы). SymPy
не разворачивает неравенства автоматически и не различает ветви по
знаку.

**По взаимному порядку выражений.** Когда после первого уровня
разбора задача содержит несколько ключевых выражений, нужен второй
уровень — по их относительному расположению. Конечное множество
ветвей — по перечислимому набору возможных порядков. Эталонная карточка: C25
(внутри ветви `a < 0` — порядок `1/a` и `−1` определяет интервал
знакопостоянства). SymPy `solve` без явного указания случая выбирает
один порядок и теряет остальные.

### 4.3. Постпроцессинг

**ОДЗ-фильтр кандидатов.** Получение от калькулятора формальных
решений и отсев тех, что не удовлетворяют ОДЗ исходного выражения.
Реализация: пост-фильтр калькулятора из §3.2, применённый *после*
делегирования — ОДЗ-предикат проверяется на каждой ветви ответа,
ветви без удовлетворения отбрасываются. Эталонная карточка: C29 (отсев
`x = −|a|` при `a ≠ 0` через `x ≥ |a|`). SymPy при возведении в
квадрат, переписывании логарифмов или делении теряет ОДЗ-условия и
возвращает посторонние корни.

**Редукция мета-вопроса о разрешимости.** Замена вопроса «при каких
параметрах задача разрешима» на эквивалентное условие на параметр,
решаемое стандартными средствами. Реализация: рерайт исходной
постановки в задачу на параметр с последующим обычным делегированием.
Два типичных подвида: *через формальное решение* — извлечение условий
вещественности или существования из символьного решения SymPy
(C27: `√(−a(a − 2))` → `−a(a − 2) ≥ 0` → `a ∈ [0, 2]`); *через
экстремум* — переписывание `∃ x: f(x) ≷ a` как условия `a` относительно
`min f` или `max f` (C28: `min f = 2`, далее `a > 2`). SymPy на
исходной формулировке метавопроса возвращает пустое множество или
`NotImplementedError`.
