## 7. Реализация в описываемой системе

Раздел показывает применение механизма §3.2 к калькулятору SymPy на
материале карточки C1 из §5.1. Реализация воспроизводит ту же
дизъюнктивную резолюцию через конкретизацию параметров правила, что
и rational_roots-правило, но крупнозернисто: единственный процедурный
символ `sympy_solve` берёт на себя всю символьную алгебру, а правило
обеспечивает обвязку по параметру задачи.

### 7.1. Символ `sympy_solve`

Процедурный символ `sympy_solve(eq, x)` — обёртка над функцией
символьного решения уравнений в SymPy. Тело символа принимает узел
`sympy_solve(eq, x)`, конвертирует термовое представление уравнения
в формат SymPy через двусторонний конвертер термов системы и
выражений CAS, выполняет вызов внешнего решателя и конвертирует ответ
обратно в термы системы — конечное множество корней `set(...)` или
пустое множество. Конвертер покрывает базовые операторы (сложение,
умножение, возведение в степень, сравнения, отношения).

### 7.2. Сквозное решение C1

Задача во входном формате системы (`tasks/sympy_comparison/parametric/c1.pbl`):

```
task {
    goal find(x);
    text "C1 — параметрическое линейное a·x = a";
    answer (a == 0 && x in Reals) || (a != 0 && x in set(1)),
           (a == 0 && x in Reals) || (a != 0 && x == 1);

    a*x == a;
    a is known;
}
```

Объявление `a is known` критично: без него правило разбора случаев с
требованием `a is known` не активируется. Решение проходит две стадии
применения правил.

**Стадия 1: канонизация.** Правило уровня 5 в `symbols/equal.sym`
переписывает уравнение в форму с нулём в правой части:

```
rule {
    attr replace, level(5), goal(find(x, ..));

    a + b == c <=> a + b - c == 0;

    !symbolic_eq(c, 0);
}
```

`a*x == a` приводится к `a*x - a == 0`, что унифицируется с шаблоном
основного правила (`x*a + b == 0`) при `b = -a`.

**Стадия 2: разбор случаев с делегированием.** Правило уровня 2 в том
же файле — ключевой артефакт настоящей работы:

```
rule {
    attr level(2), goal(find(x, ..));

    x*a + b == 0 =>
        answer(
            (a == 0 && b == 0 && x in Reals) ||
            (a == 0 && b != 0 && x in empty_set) ||
            (a != 0 && x in sympy_solve(x*a + b == 0, x))
        );

    a is known,
    b is known;
}
```

Обёртка `answer(...)` — сигнал решателю (`check_answer_term` в
`src/solver/task/solver.rs`): внутренний терм трактуется как готовый
ответ независимо от формы — здесь это дизъюнкция конъюнкций.

Из §3.2-блоков в C1 проявлены два — дизъюнктивная резолюция и
конкретизация параметров правила — плюс делегирование через
процедурный символ. В рассуждениях ниже «параметр» без
квалификатора означает параметр шаблона правила (`a, b`); параметр
задачи (одноимённый `a` из `a · x = a`) явно называется параметром
задачи. После сопоставления с шаблоном параметр правила `a`
связывается со значением, которым в данной задаче и является
параметр задачи `a`.

- **Шаблон** `x*a + b == 0` — сопоставление с шаблоном связывает
  параметры правила `a`, `b` со значениями из канонизированного
  уравнения (`a` ↦ параметр задачи `a`, `b` ↦ `−a`).
- **Конкретизация параметров правила** (в коде — метод
  `Hypothesis::ground`) связывает параметры правила и проверяет
  требования `a is known`, `b is known`; вне этих связываний правило
  не активируется.
- **Дизъюнктивная резолюция** в `answer(... || ... || ...)` фиксирует
  три ветви разбора случаев. В отличие от rational_roots-правила, где
  ветви порождаются вызовом `divisors(d)`, здесь они перечислены
  явно — допустимый альтернативный режим, когда число ветвей
  известно заранее.
- **Делегирование** в ветви `a != 0` — вызов процедурного символа
  `sympy_solve(x*a + b == 0, x)`. SymPy под допущением о ненулевом
  `a` корректно вычисляет `set(1)`.

Связывание по генератору (как `u in divisors(d)` в rational_roots) и
пост-фильтр калькулятора (как `substitute(...) == 0`) в C1 не
применяются — структура задачи не требует ни перечисления
неизвестного множества кандидатов, ни их проверки. Этот контраст
подтверждает заявленную в §3.1 инвариантность паттерна относительно
гранулярности: один и тот же логический слой обрабатывает
мелкозернистый rational_roots (пять процедурных символов, цикл по
генератору + фильтр) и крупнозернистый C1 (один символ, явная
трёхветочная резолюция).

Итог: общий ответ собирается решателем как
`(a == 0 && x in Reals) || (a != 0 && x in set(1))`, что совпадает
с эталонным `answer` в `.pbl`-файле.
