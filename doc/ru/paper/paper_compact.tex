\section{Архитектура механизма делегирования}

В описываемой системе логические правила могут обращаться к внешним
вычислениям двумя способами: \emph{вызовом подзадачи} (та же
рассуждающая машина рекурсивно решает вспомогательную задачу) и
\emph{вызовом внешнего алгоритма} (управление передаётся
детерминированной функции, реализованной за пределами правил). Оба
механизма единообразно встраиваются в правило без процедурного
контроля потока. Ниже описаны обе формы и приведён сквозной пример.

\subsection{Вызов подзадачи из правила}

Базовый механизм подзадач описан в~\cite{Solver-paper}:
\emph{подзадача} — вспомогательная задача, решаемая независимо в
рамках текущей сессии с теми же типами целевых установок
(\texttt{find}, \texttt{prove}, \texttt{transform}), результат
которой возвращается в основную задачу. Подзадачи кэшируются по
контентному ключу для повторного использования и могут рекурсивно
создавать собственные подзадачи с ограничением глубины вложенности.

Настоящая работа дополняет этот механизм \emph{явным синтаксисом
вызова подзадачи из требования правила}. В требованиях правила
может стоять блок вида \texttt{find(vars) \{ eqs; \ldots \}},
обозначающий запуск нового сеанса решения на сформированной
подзадаче поиска значений переменных \texttt{vars} при заданных
условиях \texttt{eqs}. Ответ подзадачи связывается с параметром
правила, который далее участвует в его выводе.

Внутреннее представление блока — терм-выражение
\texttt{solve(find(vars), eqs\ldots)} с отдельным головным символом
\texttt{solve}, отделяющим суб-вычисление от обычной целевой
установки \texttt{find} основной задачи. При наличии требования
\texttt{solve(find(vars), eqs\ldots) == p} решатель запускает новый
сеанс работы на сформированной подзадаче, наследуя известные
параметры родительской задачи с фильтром по неизвестным термам
подзадачи. Полученный ответ — со снятой оболочкой
\texttt{answer(\ldots)} — связывается с параметром правила $p$ и
используется в выводе.

Защита от бесконечной рекурсии — кэш сеансов суб-решения,
индексированный полным выражением \texttt{solve(find(vars),
eqs\ldots)} как контентным ключом. При повторном вхождении той же
формы (например, правило, делегирующее свою же сигнатуру в одной из
ветвей разбора) вместо нового сеанса возвращается маркер «решение
не найдено», что обрывает рекурсивную ветвь. Подзадачи с другой
структурой — меньшая степень многочлена, иная конфигурация
параметров — получают свежие ключи и решаются нормально.

Пример сочетания вызова подзадачи с обращением к внешнему алгоритму
приведён в \S2.2 на карточке C2.

\subsection{Вызов внешнего алгоритма из правила}

Параллельно механизму подзадач описываемая система поддерживает
обращение к \emph{внешнему алгоритму} — детерминированной функции,
реализованной за пределами логического слоя (встроенной в саму
систему либо обёртывающей вызов внешней системы компьютерной алгебры). Такой алгоритм оборачивается в
\emph{процедурный символ} — терм-выражение с произвольной арностью,
тело которого вычисляется не правилами, а вызовом внешней функции.

С точки зрения правила процедурный символ выглядит как обычный
терм: он может появляться в шаблоне, в требованиях правила или в
его выводе. Никаких особых конструкций для вызова делегата в языке
правил не предусмотрено. Калькулятор возвращает один из трёх типов
значений: единичный терм (числовое или символьное значение), конечное
перечислимое множество термов (\texttt{set(\ldots)}) или булеву пометку
(\texttt{true}/\texttt{false}).

Взаимодействие правила с процедурным символом раскладывается на
четыре строительных блока.

\begin{description}
  \item[Связывание по генератору.] Калькулятор возвращает конечное
    множество; параметр правила пробегает элементы этого множества
    через ключевое слово \texttt{in}: \texttt{u in divisors(d)}.
    Ветви раскрываются декартовым произведением механизмом
    конкретизации параметров правила (см.\ ниже).
  \item[Пост-фильтр калькулятора.] Калькулятор возвращает значение,
    сравниваемое с константой или другим связанным термом в
    требованиях правила; ветви, не прошедшие проверку, отбрасываются
    до резолюции. Допустимы три типичные формы: булева предикатная
    проверка применимости правила (\texttt{is\_polynomial(F, x)}),
    сравнение возвращаемого значения с константой (\texttt{d != 0})
    и пост-фильтр после связывания по генератору
    (\texttt{substitute(x == u, F) == 0}).
  \item[Конкретизация параметров правила.] Стандартный механизм
    системы: итеративно просматриваются требования вида $t = p$, где
    $p$ — свободный параметр правила, и выполняется связывание; новые
    связанные параметры раскрывают дополнительные требования на
    следующей итерации. Декартово произведение раскрывается над
    параметрами, связанными через связывание по генератору.
  \item[Дизъюнктивная резолюция.] Правая часть правила
    $(t_1) \mathrel{||} (t_2) \mathrel{||} \ldots$ формирует
    дизъюнктивный ответ из ветвей. Дизъюнктивная резолюция —
    единственный синтаксический способ выразить разбор случаев в
    тексте правила; при её отсутствии правило остаётся
    конъюнктивным.
\end{description}

Эти четыре блока образуют общую палитру; конкретное правило выбирает
подмножество, согласное со структурой задачи. Сквозной пример в
\S1.3 использует все четыре блока; параметрические правила,
обсуждаемые в \S2, — лишь два из четырёх.

\subsection{Пример}

В качестве сквозного примера рассмотрим правило поиска рациональных
корней многочлена с целыми коэффициентами. Теоретическое основание —
классическая теорема: монический многочлен с целыми коэффициентами
имеет рациональным корнем только целочисленный делитель свободного
члена. Правило формализует следствие теоремы как редукционный шаг:

\begin{lstlisting}
rule {
    attr level(5), goal(find(x, ..));

    F == 0 =>
        (x == u) || (Q == 0);

    is_polynomial(F, x),
    free_term(F, x) == d,
    d != 0,
    u in divisors(d),
    substitute(x == u, F) == 0,
    poly_div(F, x - u) == Q;
}
\end{lstlisting}

Шаблон $F = 0$ связывает параметр правила $F$ с многочленом из
условий задачи. Резолюция $(x = u) \mathrel{||} (Q = 0)$ фиксирует
найденный корень в левой ветви и редуцирует задачу к многочлену
меньшей степени в правой. В требованиях задействованы пять
процедурных символов: \texttt{is\_polynomial}, \texttt{free\_term},
\texttt{divisors}, \texttt{substitute}, \texttt{poly\_div}. Их
реализация неоднородна: часть встроена в ядро самой системы, часть
— обёртки над SymPy, использующие CAS как вспомогательный движок для
отдельных полиномиальных операций. С точки зрения правила это
различие не существенно: все пять предъявляют единый интерфейс —
терм-выражение, возвращающее терм или конечное множество.

Применение правила к задаче $F = x^3 - 6x^2 + 11x - 6$, $F = 0$, где
$x$ — искомое:

\begin{enumerate}
  \item Шаблон $F = 0$ связывает $F$ с $x^3 - 6x^2 + 11x - 6$.
  \item \texttt{free\_term(F, x)} вычисляет свободный член,
    связывая $d \mapsto -6$. Требование $d \neq 0$ выполнено.
  \item \texttt{divisors(d)} выдаёт множество
    $\{\pm 1, \pm 2, \pm 3, \pm 6\}$. Связывание $u \in
    \texttt{divisors}(d)$ раскрывает восемь ветвей.
  \item В каждой ветви \texttt{substitute(x == u, F)} вычисляется и
    сравнивается с нулём (пост-фильтр калькулятора). Ветви
    $u = 1, 2, 3$ проходят; остальные отсеиваются.
  \item Для каждой прошедшей ветви \texttt{poly\_div(F, x - u)}
    вычисляет частное $Q$. Дизъюнктивная резолюция
    $(x = u) \mathrel{||} (Q = 0)$ формирует кусочный ответ:
    три ветви с зафиксированным корнем плюс редуцированная задача
    для дальнейшей обработки.
\end{enumerate}

Подзадачи здесь не используются явно: правило самодостаточно для
своего шага. В \S2 рассмотрен случай, когда правило обращается к
внешнему алгоритму (\texttt{sympy\_solve}) для решения целой
подзадачи в одной из ветвей.


\section{Классы параметрических задач, вызывающих трудности у sympy}

Современные системы компьютерной алгебры, на примере SymPy~1.14.0
\cite{sympy}, систематически теряют решения в задачах с явным
параметром. Типичный механизм потери — деление на параметр-содержащее
выражение без явного отслеживания случая его обнуления. Аналогичные
эффекты наблюдаются при работе с радикалами (теряются ОДЗ-условия),
с модулями (нет публичного API для разбора по знаку), с
параметрическими матрицами (\texttt{rref} молча делит на
параметрические выражения), с пределами при символьном показателе
(\texttt{limit} не сравнивает порядки роста). Эти задачи в
рассуждениях ниже представлены каталогом из двенадцати
верифицированных кейсов; каждый воспроизводится минимальным
SymPy-скриптом и фиксирует механизм потери.

Раздел организован в три части. \S2.1 описывает семейство гибридных
приёмов, систематизированное по стадии применения. \S2.2 приводит
представительные карточки каталога с разбором гибридного решения.
\S2.3 фиксирует покрытие подхода и его границы.

\subsection{Решение задач с параметрами с использованием гибридного подхода}

«Логический шаг» гибридной схемы — не один трюк, а семейство
приёмов, организованное по стадии применения относительно
делегирования.

\paragraph{Предобработка.} Логический слой переписывает задачу до
делегирования. Типичные приёмы:

\begin{itemize}
  \item \emph{Факторизация выражения} — переписывание в произведение,
    открывающее перспективу разбора случаев по обнулению множителей
    через переход $a \cdot b = 0 \Rightarrow (a = 0) \mathrel{||}
    (b = 0)$.
  \item \emph{Знак-разбор модулей} — переписывание выражения с
    модулями в кусочно-линейную форму через связывание по генератору
    по бинарному множеству знаков для каждого подмодуля и
    дизъюнктивную резолюцию.
  \item \emph{Асимптотическая редукция} — замена выражения
    доминирующим членом при предельном переходе; реализуется чистым
    рерайтом без блоков делегирования.
  \item \emph{Распознавание rank-дефицита} — анализ системы линейных
    уравнений на пропорциональность строк; связывание по генератору
    по конечному множеству значений ранга и дизъюнктивная резолюция.
\end{itemize}

\paragraph{Разбор случаев.} Каноническая стадия применения паттерна:
дизъюнктивная резолюция поверх конкретизации параметров правила.
Конечный набор ветвей порождается либо связыванием по генератору с
калькулятором, выдающим перечислимое множество, либо явным
перечислением ветвей в дизъюнкции, когда их число известно заранее.
Приёмы:

\begin{itemize}
  \item \emph{По обнулению выражения} — бинарное множество ветвей
    $\{= 0, \neq 0\}$ для коэффициентов уравнения, множителей
    факторизованного коэффициента, ведущих элементов гауссовой
    процедуры.
  \item \emph{По знаку выражения} — тернарное $\{< 0, = 0, > 0\}$
    или его подмножество для коэффициента неравенства, параметра
    под корнем, показателя экспоненты.
  \item \emph{По взаимному порядку выражений} — второй уровень
    разбора, по относительному расположению ключевых выражений
    после первого.
\end{itemize}

\paragraph{Постпроцессинг.} Логический слой фильтрует или
интерпретирует ответ калькулятора:

\begin{itemize}
  \item \emph{ОДЗ-фильтр кандидатов} — пост-фильтр калькулятора,
    применённый \emph{после} делегирования: ОДЗ-предикат
    проверяется на каждой ветви ответа SymPy, ветви, не
    удовлетворяющие ОДЗ, отбрасываются.
  \item \emph{Редукция мета-вопроса о разрешимости} — переписывание
    исходной постановки в задачу на параметр с последующим обычным
    делегированием (через формальное решение или через экстремум).
\end{itemize}

Сборка ветвей — общий финальный шаг во всех приёмах, выражаемый
дизъюнктивной резолюцией из \S1.

\subsection{Примеры}

\paragraph{C1 --- параметрическое линейное уравнение
$a \cdot x = a$.} \texttt{SymPy.solve(Eq(a*x, a), x)} возвращает
$[1]$, теряя случай $a = 0$, в котором уравнение становится
тождеством. Гибридный путь --- разбор случаев по обнулению
коэффициента и делегирование SymPy в ветви $a \neq 0$.
В реализации правило выглядит так:

\begin{lstlisting}
rule {
    attr level(2), goal(find(x, ..));

    x*a + b == 0 =>
        answer(
            (a == 0 && b == 0 && x in Reals) ||
            (a == 0 && b != 0 && x in empty_set) ||
            (a != 0 && x in sympy_solve(x*a + b == 0, x))
        );

    a is known,
    b is known;
}
\end{lstlisting}

Из четырёх блоков \S1.2 здесь проявлены два: конкретизация параметров
правила (связывание $a, b$ из шаблона, проверка требований
\texttt{a is known}, \texttt{b is known}) и дизъюнктивная резолюция
(трёхветочный \texttt{answer}). Связывание по генератору и
пост-фильтр калькулятора не используются: число ветвей известно
заранее. Делегирование в ветви $a \neq 0$ обращается к процедурному
символу \texttt{sympy\_solve}, который под допущением о ненулевом
$a$ возвращает \texttt{set(1)}.

Итог: общий ответ собирается как
$(a = 0 \,\&\&\, x \in \mathbb{R}) \mathrel{||} (a \neq 0 \,\&\&\,
x = 1)$.

\paragraph{C29 --- параметрическое иррациональное уравнение
$\sqrt{x - a} + \sqrt{x + a} = \sqrt{2x}$.}
\texttt{solveset(\ldots, S.Reals)} возвращает $\{-|a|, |a|\}$, не
учитывая ОДЗ $x \geq |a|$. Корень $x = -|a|$ удовлетворяет ОДЗ
только при $a = 0$. Гибридный путь: SymPy решает формальную алгебру
(возведением в квадрат), затем логический слой применяет ОДЗ-фильтр
(пост-фильтр калькулятора, применённый \emph{после} делегирования) и
отсеивает $x = -|a|$ в ветви $a \neq 0$. Итог: $a = 0 \Rightarrow
x = 0$; $a \neq 0 \Rightarrow x = |a|$.

\paragraph{C21 --- параметрическая \texttt{rref} матрицы.}
\texttt{A.rref()} над $4 \times 4$ матрицей с параметрами $\nu,
\lambda$ возвращает ступенчатую форму, в которой ведущие элементы
$\nu$, $\nu^2$, $\lambda + \nu$ встают в знаменатели правого
столбца, причём случай их обнуления не отслеживается. Гибридный
путь: идентификация будущих ведущих элементов, разбор на три ветви
(общий случай $\nu \neq 0 \wedge \lambda + \nu \neq 0$; $\nu = 0$;
$\lambda + \nu = 0$), делегирование \texttt{A.rref()} в каждой
ветви под допущением о ненулевом ведущем. Карточка показывает, что
разбор случаев применим не только к \texttt{solve} и
\texttt{solveset}, но и к другим алгоритмам CAS, использующим
неявное деление на параметрические выражения.

\paragraph{C2 --- параметрическое квадратное уравнение $(a^2 - 1)
\cdot x^2 + 2(a - 1) \cdot x + 1 = 0$.} \texttt{solve(\ldots)}
возвращает пару корней с $(a^2 - 1)$ в знаменателе и $2 - 2a$ под
корнем; при $a = 1$ обе формулы вырождаются ($0/0$), при $a = -1$
знаменатель обнуляется. SymPy не разбирает старший коэффициент и не
замечает, что при $a = \pm 1$ тип уравнения меняется (при $a = 1$
одновременно обнуляется и линейный коэффициент). Гибридный путь --
двухуровневый разбор случаев на универсальном правиле квадратного
уравнения $a \cdot x^2 + b \cdot x + c = 0$:

\begin{lstlisting}
rule {
    attr level(2), goal(find(x, ..));

    a*x^2 + b*x + c == 0 =>
        answer(
            (a == 0 && lin) ||
            (a != 0 && x in sympy_solve(a*x^2 + b*x + c, x))
        );

    a is known,
    b is known,
    c is known,
    lin == find(x) { b*x + c == 0; b is known; c is known };
}
\end{lstlisting}

В ветви $a \neq 0$ правило делегирует уравнение целиком символу
\texttt{sympy\_solve} (\S1.2). В ветви $a = 0$ требование
\texttt{lin == find(x) \{ b*x + c == 0; \ldots \}} обращается к
подзадаче (\S1.1) на линейном уравнении $b \cdot x + c = 0$ с
известными $b$ и $c$; ответ подзадачи (полученный применением
соседнего правила линейного разбора случаев) связывается с параметром
\texttt{lin}. Применение правила к C2 даёт кусочный ответ
\[
  (a = 1 \wedge x \in \emptyset)
  \mathrel{||}
  (a = -1 \wedge x = 1/4)
  \mathrel{||}
  \bigl(a \neq \pm 1 \wedge x \in
  \tfrac{- a + 1 \pm \sqrt{2 - 2a}}{a^2 - 1}\bigr).
\]
Ветви $a = \pm 1$ возникают рекурсивно: при $a = 1$ подзадача
получает $b = 0, c = 1$ → противоречие → $\emptyset$; при $a = -1$ —
$b = -4, c = 1$ → $x = 1/4$ через \texttt{sympy\_solve}. Карточка
демонстрирует одновременное использование обоих механизмов
делегирования из \S1: подзадача (\S1.1) обрабатывает вырожденную
ветвь после редукции, внешний CAS (\S1.2) — невырожденную; логика
разбора по обнулению старшего коэффициента остаётся на стороне
правила.

\subsection{Результаты}

Каталог из двенадцати верифицированных параметрических кейсов на
SymPy~1.14.0 организован по двум осям: структуре объекта (одиночные
уравнения, неравенства, системы) и тому, что требуется найти
(значение неизвестного, существование, число решений, локализация,
доказательство $\forall a$, оптимизация). Из тридцати ячеек
получившейся сетки заполнены пять.

Колонка $\forall a$ оставлена пустой сознательно: задачи на
доказательство тождеств решаются чисто логическими преобразованиями
без делегирования, и в гибридный фокус не попадают. Остальные
пустоты (число решений, локализация, оптимизация, параметрические
системы с неравенствами) --- направления естественного расширения
каталога, не покрытые текущей выборкой.

Сводная карта <<приём $\times$ карточка>> показывает количественную
неравномерность: разбор случаев --- восемь карточек из двенадцати,
постпроцессинг (ОДЗ-фильтр и редукция мета-вопроса) --- три,
специальные приёмы предобработки (знак-разбор модулей, rank-дефицит,
асимптотическая редукция) --- по одной карточке. Задачи в пустых
колонках сетки преимущественно требуют постпроцессинговых приёмов и
разбора по взаимному порядку --- то есть приёмов, представленных в
каталоге слабее всего. Сетка постановок и карта приёмов независимо
указывают на одни и те же области для расширения.

Архитектурные пределы гибридной схемы --- классы задач, в которых
нет естественной декомпозиции на координационный логический слой и
детерминированный калькулятор:

\begin{itemize}
  \item монолитные алгоритмы без промежуточной формы для разбора
    случаев (алгоритм Риша для интегрирования; базисы Гребнера без
    предварительной факторизации; арифметика над \texttt{RootOf});
  \item чисто логические задачи без алгебраической составляющей
    (\texttt{prove $\forall a$});
  \item экспоненциальный рост числа ветвей при последовательном
    применении нескольких разборов случаев в задачах с многими
    параметрами одновременно.
\end{itemize}

Архитектурного решения для последнего ограничения в работе не
предлагается; типичные стратегии --- отсечение ветвей по предикатам
несовместности, переупорядочивание разбора случаев от грубых к
точным --- относятся к открытым направлениям.
