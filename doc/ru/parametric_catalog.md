## Каталог параметрических задач: гибридное решение

### Назначение

Рабочий артефакт направления «комбинирование детерминированных алгоритмов с
логическим подходом при решении задач». Документ ведёт пул задач с
параметрами, на которых SymPy объективно проигрывает, и для каждой даёт
гибридный путь: логический шаг (case-split, ОДЗ-фильтр, факторизация) +
делегирование подзадачи в SymPy.

Документ — основной материал для черновика статьи и обсуждения с научным
руководителем.

### Связь с предшественником

Каталог [`sympy_catalog.md`](sympy_catalog.md) — более широкая выборка
провалов SymPy без сужения по параметру. Он остаётся как архивный материал
и здесь не дублируется. В этот файл переносятся только карточки, в которых
центральным шагом решения является логическое рассуждение по параметру.

### Версия SymPy

Все наблюдения зафиксированы на **SymPy 1.14.0** (январь 2026). Repro-скрипты
регрешн-suite — в [`doc/sympy_audit/`](../sympy_audit/).

### Тезис

SymPy умеет считать, но не делает простых логических шагов:

- разбор по случаям, когда коэффициент обнуляется;
- разбор по знаку выражения (модуль, неравенство, разворот знака);
- отслеживание ОДЗ при возведении в степень, логарифмировании, делении;
- факторизация выражения до запуска тяжёлой машинерии (Гребнер).

Без этих шагов CAS возвращает неполный или неверный ответ. Гибридная схема:

1. **Логический шаг (laffie).** Задача распадается на ветви, в каждой из
   которых параметр устранён или зафиксирован знаком.
2. **Делегирование (SymPy).** В каждой ветви классическая алгебра без
   неоднозначности, SymPy решает её детерминированно и корректно.
3. **Сборка.** Ветви объединяются в кусочный или дизъюнктивный ответ.

Логический шаг — не один приём, а семейство: case-split по параметру,
case-split по знаку, ОДЗ-фильтр, факторизация-до-делегирования, введение
дискретного параметра серии решений. Каждый класс задач разбирается своим
приёмом.

### Типы постановок

**По структуре объекта:**

- одиночное уравнение;
- одиночное неравенство;
- система уравнений;
- система неравенств;
- смешанная система (уравнения + неравенства).

**По тому, что требуется найти:**

- решить относительно неизвестной (find `x`);
- найти параметр, при котором задача разрешима;
- найти параметр по числу решений (ровно `N` корней);
- найти параметр по локализации решений (корни в заданном множестве);
- доказать свойство для всех значений параметра;
- параметрическая оптимизация (max/min по параметру).

Перекрёстная сетка «структура × что искать» используется для контроля
покрытия и поиска пробелов в каталоге.

### Шаблон карточки

```
#### Cn — короткое имя и формула

- Постановка: математическая формулировка с явным параметром и неизвестной.
- Тип постановки: <словами, по двум осям выше>.
- Поведение SymPy: код вызова → результат на 1.14.0.
- Что не так: что именно SymPy теряет / искажает.
- Правильный ответ: ожидаемый ответ (кусочно по параметру).

Гибридный путь (краткое имя приёма):

1. Логический шаг. Что разбирает laffie до делегирования.
2. Делегирование SymPy. Что в каждой ветви корректно вычисляет SymPy.
3. Сборка. Как объединяются ветви в финальный ответ.

- Источник: откуда задача.
- Заметка (опционально): дополнения.
```

## Карточки

### Одиночные уравнения

#### C1 — параметрическое линейное `a·x = a`

- **Постановка**: решить относительно `x` уравнение `a·x = a` с параметром `a`.
- **Тип постановки**: одиночное уравнение, ищем `x`.
- **Поведение SymPy**: `solve(Eq(a*x, a), x)` возвращает `[1]` — единственный
  ответ `x = 1`.
- **Что не так**: SymPy делит обе части на `a` без проверки `a ≠ 0` и теряет
  случай `a = 0`, в котором уравнение становится тождеством `0 = 0` и любой
  `x` подходит.
- **Правильный ответ**:
  - при `a = 0` — любое `x`;
  - при `a ≠ 0` — `x = 1`.

**Гибридный путь** (case-split по параметру):

1. *Логический шаг.* Разбираем по обнулению коэффициента при `x`: ветви
   `a = 0` и `a ≠ 0`.
2. *Делегирование SymPy.* В ветви `a ≠ 0` ответ SymPy `[1]` уже корректен —
   он покрывает именно эту ветвь; гибрид использует его как есть. В ветви
   `a = 0` уравнение сводится к тождеству `0 = 0`, CAS не нужен.
3. *Сборка.* Кусочный ответ: «если `a = 0`, то любое `x`; иначе `x = 1`».

- **Источник**: классическое упражнение по разбору параметрического линейного
  уравнения; локальная верификация.

#### C24 — параметрическое линейное `(a² − 4)·x = a − 2`

- **Постановка**: решить относительно `x` уравнение `(a² − 4)·x = a − 2`.
- **Тип постановки**: одиночное уравнение, ищем `x`.
- **Поведение SymPy**: `solve(...)` → `[1/(a + 2)]`; `solveset` →
  `{(a − 2)/(a² − 4)}` (та же ветвь без сокращения).
- **Что не так**: SymPy сокращает `(a − 2)` и делит на `(a + 2)`, теряя обе
  вырожденные ветви.
- **Правильный ответ**: после факторизации `(a − 2)(a + 2)·x = (a − 2)`:
  - `a = 2` — `0 = 0`, любое `x`;
  - `a = −2` — `0 = −4`, решений нет;
  - иначе — `x = 1/(a + 2)`.

**Гибридный путь** (case-split по обнулению множителей коэффициента):

1. *Логический шаг.* Раскладываем `(a² − 4) = (a − 2)(a + 2)`. Три ветви:
   `a = 2`, `a = −2`, `a ≠ ±2`.
2. *Делегирование SymPy.* `a = 2` — тождество, любое `x`. `a = −2` —
   противоречие, `∅`. `a ≠ ±2` — SymPy под допущением о ненулевом множителе
   даёт `x = 1/(a + 2)`.
3. *Сборка.* Кусочный ответ.

- **Источник**: Сканави, параметрические уравнения.
- **Заметка**: расширение C1 — два независимых вырождения параметра одним
  вызовом.

#### C2 — параметрическое квадратное `(a² − 1)·x² + 2(a − 1)·x + 1 = 0`

- **Постановка**: решить относительно `x` уравнение
  `(a² − 1)·x² + 2(a − 1)·x + 1 = 0`.
- **Тип постановки**: одиночное уравнение, ищем `x`.
- **Поведение SymPy**: возвращает пару корней с `(a² − 1)` в знаменателе и
  `2 − 2a` под корнем; в `a = 1` обе формулы вырождаются (`0/0`), в `a = −1`
  знаменатель — 0.
- **Что не так**: SymPy не разбирает старший коэффициент `a² − 1` и не
  замечает, что при `a = ±1` тип уравнения меняется. В `a = 1` одновременно
  обнуляется и линейный коэффициент `2(a − 1)`.
- **Правильный ответ**:
  - `a = 1` — уравнение `1 = 0`, решений нет;
  - `a = −1` — линейное `−4x + 1 = 0`, `x = 1/4`;
  - иначе — квадратное общего вида.

**Гибридный путь** (двухуровневый разбор по обнулению коэффициентов):

1. *Логический шаг.* Сначала по обнулению старшего коэффициента
   `(a² − 1) = (a − 1)(a + 1)`; внутри `a = 1` — по обнулению линейного
   `2(a − 1)`. Три ветви: `a = 1` (оба нуль), `a = −1` (только старший нуль),
   `a ≠ ±1`.
2. *Делегирование SymPy.* `a = 1` — противоречие `1 = 0`, `∅` (CAS не нужен).
   `a = −1` — SymPy решает линейное `−4x + 1 = 0` → `x = 1/4`. `a ≠ ±1` —
   SymPy под допущением о ненулевом старшем коэффициенте корректно вычисляет
   квадратные формулы.
3. *Сборка.* Три кусочные ветви.

- **Источник**: классический параметрический пример с двумя вырождениями
  старшего коэффициента; локальная верификация.

#### C26 — биквадратное с параметром `x⁴ − (a + 1)·x² + a = 0`

- **Постановка**: найти все вещественные `x`, удовлетворяющие
  `x⁴ − (a + 1)·x² + a = 0`.
- **Тип постановки**: одиночное уравнение, ищем `x`.
- **Поведение SymPy**: `solve(...)` → `[−1, 1, −sqrt(a), sqrt(a)]` (без отбора
  по вещественности); `solveset(..., S.Reals)` →
  `Intersection({−1, 1, −sqrt(a), sqrt(a)}, Reals)` — невычислено.
  `factor(...)` корректно даёт `(x² − 1)(x² − a)`.
- **Что не так**: после факторизации ветвь `x² = a` обрабатывается без анализа
  знака `a`. Корни `±√a` вещественны только при `a ≥ 0`. SymPy не сворачивает
  `Intersection` с `Reals`.
- **Правильный ответ**:
  - `a < 0` — `{−1, 1}`;
  - `a = 0` — `{−1, 0, 1}`;
  - `0 < a, a ≠ 1` — `{−1, 1, −√a, √a}`;
  - `a = 1` — `{−1, 1}` (двойные корни).

**Гибридный путь** (факторизация + case-split по знаку):

1. *Логический шаг.* Применяем тождество `x⁴ − (a + 1)x² + a = (x² − 1)(x² − a)`.
   Первый множитель даёт `±1` без условий. Для второго (`x² = a`) разбираем
   по знаку `a`: `a < 0` (нет вещественных корней), `a = 0` (один корень
   `x = 0`), `a > 0` (`±√a`; особый подслучай `a = 1` — корни ±√a совпадают
   с ±1).
2. *Делегирование SymPy.* В ветви `a > 0` SymPy под допущением о
   положительности `a` корректно даёт `x = ±√a`. Ветви `a = 0` (тривиально
   `x = 0`) и `a < 0` (по правилу «`x² = c` имеет вещественный корень iff
   `c ≥ 0`» — пусто) разрешаются логикой без CAS.
3. *Сборка.* Объединение базовых `±1` с корнями второго множителя по ветвям.

- **Источник**: Сканави, биквадратное с параметром.
- **Заметка**: типичный кейс «`factor` работает, `Intersection` с `Reals` не
  свёрнут».

#### C29 — параметрическое иррациональное `√(x − a) + √(x + a) = √(2x)`

- **Постановка**: решить относительно `x` уравнение
  `√(x − a) + √(x + a) = √(2x)` с параметром `a ∈ ℝ`.
- **Тип постановки**: одиночное уравнение, ищем `x`.
- **Поведение SymPy**: `solve(...)` → `[−a, a]`; `solveset(..., S.Reals)` →
  `{−|a|, |a|}`.
- **Что не так**: ОДЗ исходного — `x ≥ |a|`. Возведение в квадрат формально
  даёт `x² = a²` и кандидатов `±|a|`. Корень `x = −|a|` удовлетворяет ОДЗ
  только при `a = 0`. SymPy не выполняет постфильтр по ОДЗ.
- **Правильный ответ**:
  - `a = 0` — `x = 0`;
  - `a ≠ 0` — `x = |a|`.

**Гибридный путь** (формальное решение + ОДЗ-фильтр):

1. *Логический шаг.* Выписываем ОДЗ исходного уравнения: `x ≥ |a|` (из
   неотрицательности всех подкоренных). Это фильтр, который будет применён
   к формальным кандидатам после делегирования.
2. *Делегирование SymPy.* SymPy решает уравнение возведением в квадрат и
   возвращает кандидатов `[−a, a]` (или `{−|a|, |a|}` через `solveset`) —
   формальная алгебра корректна, проблема только в отсутствии ОДЗ-фильтра.
3. *Сборка.* Применяем ОДЗ к каждому кандидату: `+|a| ≥ |a|` — проходит,
   `−|a| ≥ |a|` — проходит только при `a = 0`. Итоговый кусочный ответ:
   `a = 0` → `x = 0`; `a ≠ 0` → `x = |a|`.

- **Источник**: Сканави.
- **Заметка**: ОДЗ-провал с параметром. `solveset` переписывает в `{−|a|, |a|}`,
  но case-split по знаку `a` для отсева не делает.

#### C23 — параметрический предел при `x → +∞`

- **Постановка**: вычислить `lim_{x→+∞} (x·e^x − e^{2√(1+x²)}) / (e^{α·x} + x^α)`
  при `α > 0`.
- **Тип постановки**: одиночный предел; ищем значение как функцию `α`.
- **Поведение SymPy**: `limit(...)` → невычисленный `Limit(...)`. Подстановка
  конкретных значений работает: `α = 2 → −1`, `α = 1/2 → −∞`, `α = 3 → 0`.
- **Что не так**: `limit` не делает case-split по параметру и не сравнивает
  порядки роста экспонент с символьным `α`. На конкретном `α` справляется, на
  символьном — no progress.
- **Правильный ответ** (числитель `∼ −e^{2x}`, знаменатель `∼ e^{α·x}`):
  - `α < 2` — `−∞`;
  - `α = 2` — `−1`;
  - `α > 2` — `0`.

**Гибридный путь** (асимптотическая редукция + case-split по знаку показателя):

1. *Логический шаг.* Доминирующий член числителя при `x → +∞` — `−e^{2x}`
   (поскольку `e^{2√(1+x²)} ∼ e^{2x}` обгоняет `x·e^x`). Доминирующий член
   знаменателя — `e^{α·x}` (любая экспонента с `α > 0` обгоняет `x^α`).
   Сравнение показателей `2` и `α` даёт три ветви: `α < 2`, `α = 2`, `α > 2`.
2. *Делегирование SymPy.* В каждой ветви `α` фиксирован относительно `2`,
   и `limit` справляется на конкретном представителе: `α = 1 → −∞`,
   `α = 2 → −1`, `α = 3 → 0`. То есть после устранения параметрической
   неопределённости предел вычисляется детерминированно.
3. *Сборка.* Три кусочных значения по `α`.

- **Источник**: StackOverflow [#59995637](https://stackoverflow.com/questions/59995637).
- **Заметка**: параметрический case-split применим не только в `solve`, но и в
  `limit`.

### Одиночные неравенства

#### C10 — параметрическое линейное неравенство `a·x > b`

- **Постановка**: решить относительно `x` неравенство `a·x > b` при
  произвольных `a, b ∈ ℝ`.
- **Тип постановки**: одиночное неравенство, ищем `x`.
- **Поведение SymPy**: `reduce_inequalities([a*x > b], [x])` возвращает
  входное `a·x > b` без обработки.
- **Что не так**: SymPy не различает деление на положительное и отрицательное
  (с разворотом знака) и не разбирает вырожденный `a = 0`.
- **Правильный ответ**:
  - `a > 0` — `x > b/a`;
  - `a < 0` — `x < b/a` (знак развёрнут);
  - `a = 0, b < 0` — `x ∈ ℝ`;
  - `a = 0, b ≥ 0` — `∅`.

**Гибридный путь** (case-split по знаку коэффициента):

1. *Логический шаг.* Разбор по знаку `a`: `a > 0`, `a < 0`, `a = 0`. В
   ненулевых ветвях правило «при делении на отрицательное знак неравенства
   разворачивается». В `a = 0` неравенство `0 > b` — тождество либо
   противоречие в зависимости от знака `b`.
2. *Делегирование SymPy.* В ненулевых ветвях SymPy под допущением о знаке `a`
   корректно решает `x ≷ b/a`. В вырожденной ветви — простой разбор по знаку
   `b`, CAS не нужен.
3. *Сборка.* Четыре кусочных ответа.

- **Источник**: локальная верификация.

#### C25 — параметрическое квадратичное неравенство `a·x² + (a − 1)·x − 1 > 0`

- **Постановка**: решить относительно `x` неравенство
  `a·x² + (a − 1)·x − 1 > 0`.
- **Тип постановки**: одиночное неравенство, ищем `x`.
- **Поведение SymPy**: `reduce_inequalities(...)` → `NotImplementedError`;
  `solveset(..., S.Reals)` → `ConditionSet`.
- **Что не так**: ни одно API не разбирает параметрический случай. Тип
  неравенства зависит от знака `a` (направление параболы) и от взаимного
  порядка корней `1/a` и `−1`.
- **Правильный ответ** (после факторизации `(a·x − 1)(x + 1) > 0`):
  - `a > 0` — `x < −1` или `x > 1/a`;
  - `a = 0` — `x < −1`;
  - `−1 < a < 0` — `1/a < x < −1`;
  - `a = −1` — `∅` (касание оси);
  - `a < −1` — `−1 < x < 1/a`.

**Гибридный путь** (двухуровневый разбор: знак `a` + порядок корней):

1. *Логический шаг.* Сначала по знаку `a` (`a > 0` / `a = 0` / `a < 0`).
   Внутри `a < 0` — второй уровень по порядку корней: `a = −1` (корни
   совпадают), `−1 < a < 0` (`1/a < −1`), `a < −1` (`−1 < 1/a < 0`).
2. *Делегирование SymPy.* После факторизации в каждой ветви параметр
   зафиксирован знаком и расположением корней; SymPy корректно вычисляет
   интервалы знакопостоянства.
3. *Сборка.* Пять кусочных ветвей.

- **Источник**: Сканави, параметрические неравенства.
- **Заметка**: квадратичное обобщение C10. Внутри `a < 0` — типичный паттерн
  вложенного ветвления.

#### C28 — при каких `a` неравенство `|x − 1| + |x + 1| < a` имеет решение

- **Постановка**: найти все `a`, при которых неравенство
  `|x − 1| + |x + 1| < a` имеет хотя бы одно решение `x`.
- **Тип постановки**: одиночное неравенство, ищем `a` (по разрешимости).
- **Поведение SymPy**: `reduce_inequalities(...)` → `NotImplementedError`;
  `solveset(..., S.Reals)` → `ConditionSet`. Дополнительно:
  `minimum(|x−1| + |x+1|, x)` тоже бросает `NotImplementedError` — нижнюю
  границу через критические точки SymPy не извлекает.
- **Что не так**: нет API «при каких `a` ∃ `x: f(x) < a`», и нет API минимума
  суммы модулей. Без знак-разбора SymPy не двигается.
- **Правильный ответ**: `a > 2`. Минимум `f(x) = |x−1| + |x+1|` равен `2`
  (достигается на отрезке `[−1, 1]`).

**Гибридный путь** (знак-разбор модулей + редукция к экстремуму):

1. *Логический шаг.* Знак-разбор обоих модулей даёт кусочно-линейную форму
   `f(x)`: `−2x` при `x < −1`, `2` при `−1 ≤ x ≤ 1`, `2x` при `x > 1`. Условие
   разрешимости `f(x) < a` сводится к `a > minₓ f`.
2. *Делегирование SymPy.* На каждом кусочном выражении SymPy находит минимум
   на своём интервале — стандартная задача без знак-разбора: `−2x` на
   `(−∞, −1]` достигает минимума `2` в `x = −1`, константа `2` на `[−1, 1]`,
   `2x` на `[1, +∞)` достигает минимума `2` в `x = 1`. Общий минимум — `2`.
3. *Сборка.* Условие на `a`: `a > 2`.

- **Источник**: Сканави.
- **Заметка**: знак-разбор модулей — типичный приём; SymPy буксует на сумме
  модулей даже в `minimum`.

### Системы уравнений

#### C11 — переопределённая линейная система с параметром

- **Постановка**: найти `(x, y)` для системы `{ x + y = 1, 2x + 2y = p }` с
  параметром `p`.
- **Тип постановки**: система уравнений, ищем `(x, y)`.
- **Поведение SymPy**: `solve([x+y-1, 2*x+2*y-p], [x, y])` → `[]`.
- **Что не так**: вторая строка пропорциональна первой (× 2), система имеет
  ранг 1; при `p = 2` строки совместны и есть однопараметрическое семейство,
  при `p ≠ 2` — нет. SymPy выдаёт «пусто», как будто решений нет ни при каком
  `p`.
- **Правильный ответ**:
  - `p = 2` — `{ (x, 1 − x) : x ∈ ℝ }`;
  - `p ≠ 2` — `∅`.

**Гибридный путь** (rank-дефицит + условие согласованности):

1. *Логический шаг.* Замечаем линейную зависимость строк: вторая = `2 ×`
   первая. Условие согласованности правых частей: `p = 2 · 1 = 2`. Ветви
   `p = 2` и `p ≠ 2`.
2. *Делегирование SymPy.* `p = 2` — система сводится к одному уравнению
   `x + y = 1`; `linsolve` параметризует с одной свободной переменной.
   `p ≠ 2` — уравнения противоречат друг другу, `∅`.
3. *Сборка.* Кусочный ответ.

- **Источник**: локальная верификация.

#### C21 — `rref` параметрической матрицы

- **Постановка**: привести к ступенчатому виду `4×4` матрицу с параметрами
  `ν, λ`:
  ```
  ⎡−3ν     1          0          0⎤
  ⎢ 3ν   −2ν−1        2          0⎥
  ⎢ 0     2ν       −ν−λ−2        3⎥
  ⎣ 0     0         ν+λ         −3⎦
  ```
- **Тип постановки**: задача линейной алгебры с параметрами; ищем ступенчатую
  форму.
- **Поведение SymPy**: `A.rref()` возвращает первые три строки единичной формы
  с правым столбцом `[−1/(λν²+ν³), −3/(λν+ν²), −3/(λ+ν), 0]ᵀ` — делит на
  множители `ν`, `ν²`, `(λ+ν)`.
- **Что не так**: `rref` молча делит на параметрические выражения. При `ν = 0`
  или `λ + ν = 0` выбираемый pivot равен нулю и структура ступенчатой формы
  меняется. Публичного API для case-split-ответа нет.
- **Правильный ответ** (piecewise):
  - общий случай (`ν ≠ 0 ∧ λ + ν ≠ 0`) — указанная форма;
  - `ν = 0` — pivot-столбцы `(1, 2, 3)` вместо `(0, 1, 2)`;
  - `λ + ν = 0` — pivot-столбцы `(0, 1, 3)`.

**Гибридный путь** (case-split по обнулению pivot-ов):

1. *Логический шаг.* Идентифицируем выражения, на которые гауссова процедура
   хочет делить, — это будущие pivot-ы: `ν` (старший) и `λ + ν`. Три ветви.
2. *Делегирование SymPy.* В каждой ветви параметры либо имеют известное
   значение, либо ограничены ненулевыми; в этом виде `A.rref()` даёт корректную
   форму без скрытых делений.
3. *Сборка.* Piecewise по `(ν, λ + ν)` — три варианта структуры.

- **Источник**: StackOverflow [#19072700](https://stackoverflow.com/questions/19072700).
- **Заметка**: то же координационное «делю и не сообщаю» происходит в `rref`,
  как и в `solve`. Гибридный приём — case-split по обнулению pivot —
  идентичен.

#### C27 — при каких `a` система `{ x + y = a, x² + y² = a }` разрешима в ℝ

- **Постановка**: найти все `a`, при которых система имеет хотя бы одно
  вещественное решение `(x, y)`.
- **Тип постановки**: система уравнений с параметром, ищем `a` (по
  разрешимости).
- **Поведение SymPy**: `solve(...)` возвращает формальную параметризацию
  через `√(−a(a − 2))`. Прямого API «при каких `a` ∃ вещественное решение»
  нет.
- **Что не так**: SymPy выдаёт формулы корней, не сообщая, что подкоренное
  `−a(a − 2)` может быть отрицательным. Нет режима «existence as set of
  parameter values».
- **Правильный ответ**: `a ∈ [0, 2]` — из условия `−a(a − 2) ≥ 0`.

**Гибридный путь** (мета-извлечение условий разрешимости):

1. *Логический шаг.* Берём формальное решение от SymPy. Извлекаем подкоренные
   выражения, в которых может оказаться отрицательное значение, — получаем
   условие разрешимости в ℝ: `−a(a − 2) ≥ 0`.
2. *Делегирование SymPy.* Полученное условие — обычное полиномиальное
   неравенство относительно `a`. `solveset(−a(a−2) ≥ 0, a, S.Reals)` корректно
   даёт `Interval(0, 2)`.
3. *Сборка.* Полученный интервал — финальный ответ.

- **Источник**: классическая олимпиадная задача (Москва, вступительные).
- **Заметка**: метакатегория «при каких параметрах разрешимо». ЕГЭ-задание 18
  относится к тому же классу.

## Семейство гибридных приёмов

В двенадцати карточках выше «логический шаг» — не один трюк, а семейство.
Приёмы организованы по тому, в каком месте гибридной схемы они подключаются:

- **Предобработка** — laffie преобразует исходную задачу в форму, к которой
  делегирование осмысленно.
- **Case-split** — laffie разбивает задачу на ветви с фиксированным знаком
  или значением выражений.
- **Постпроцессинг** — laffie фильтрует или интерпретирует ответ SymPy.

Сборка ветвей — общий финальный шаг во всех карточках, отдельно не
выделяется.

В одной карточке обычно используется композиция нескольких приёмов
(например, факторизация → case-split по знаку, или формальное решение →
ОДЗ-фильтр).

### Предобработка

#### Факторизация выражения

Преобразование выражения в произведение — открывает перспективу case-split
по обнулению множителей или по знаку каждого. SymPy умеет факторизовать
через `factor()`, но не использует разложение для дальнейшего разбора.

Применение: C2 (`a² − 1 = (a − 1)(a + 1)`), C24 (`a² − 4 = (a − 2)(a + 2)`),
C25 (`(a·x − 1)(x + 1)`), C26 (`(x² − 1)(x² − a)`).

#### Знак-разбор модулей

Преобразование выражения с модулями в кусочно-линейную (или кусочно-полиномиальную) форму через разбор по знакам подмодульных выражений. SymPy
публичного API на это не даёт.

Применение: C28 (`|x − 1| + |x + 1|` → кусочная функция).

#### Асимптотическая редукция

Замена выражения на доминирующий член при предельном переходе (определяется
через сравнение порядков роста). SymPy справляется на конкретных значениях,
но не делает символьного сравнения порядков с параметром.

Применение: C23 (`x·e^x − e^{2√(1+x²)} ∼ −e^{2x}` при `x → +∞`).

#### Распознавание rank-дефицита

Анализ системы линейных уравнений на пропорциональность строк; при
обнаружении — построение условия согласованности правых частей. SymPy
выдаёт пустое множество без объяснения причины.

Применение: C11 (`{x + y = 1, 2x + 2y = p}` → условие `p = 2`).

### Case-split

#### По обнулению выражения

Ветвление по тому, обнуляется ли в задаче критическое выражение: коэффициент
уравнения, множитель факторизованного коэффициента, pivot гауссовой
процедуры. SymPy в этих случаях молча делит и теряет вырожденную ветвь.

Применение: C1 (коэффициент `a`), C24 (множители `a − 2`, `a + 2`),
C2 (двухуровневый: старший и линейный коэффициенты), C21 (pivot `ν`,
`λ + ν` в `rref`).

#### По знаку выражения

Ветвление по знаку: знака коэффициента (определяет, разворачивается ли
неравенство при делении), знака параметра под корнем (определяет
вещественность), знака показателя экспоненты (определяет поведение в
пределе).

Применение: C10 (знак `a` в `a·x > b`), C26 (знак `a` в `x² = a`),
C23 (знак показателя `2 − α`), C25 (знак `a` для направления параболы).

#### По взаимному порядку выражений

Когда после первого case-split задача содержит несколько ключевых выражений
(например, корней параметрического полинома), нужен второй уровень разбора —
по их относительному расположению.

Применение: C25 (внутри ветви `a < 0` — порядок `1/a` и `−1` определяет
интервал знакопостоянства).

### Постпроцессинг

#### ОДЗ-фильтр кандидатов

Получение от SymPy формальных решений и отсев тех, что не удовлетворяют
ОДЗ исходного выражения. SymPy при возведении в квадрат / переписывании
логарифмов / делении теряет ОДЗ-условия.

Применение: C29 (отсев `x = −|a|` при `a ≠ 0` через `x ≥ |a|`).

#### Редукция мета-вопроса о разрешимости

Замена вопроса «при каких параметрах задача разрешима» на эквивалентное
условие на параметр, которое решается стандартными CAS-средствами. Два
типичных подвида:

- *Через формальное решение.* SymPy возвращает параметрическое решение
  (часто через корень или дробь); из него извлекаются условия
  вещественности / существования (подкоренное ≥ 0, знаменатель ≠ 0). Эти
  условия — обычные неравенства, которые SymPy умеет решать по параметру.
  Применение: C27 (`√(−a(a − 2))` → `−a(a − 2) ≥ 0` → `a ∈ [0, 2]`).
- *Через экстремум.* Вопрос «∃ `x`: `f(x) ≷ a`» переписывается как
  условие `a` относительно `min f` или `max f`, после чего экстремум
  вычисляется стандартно.
  Применение: C28 (`∃ x: f(x) < a ⇔ a > minₓ f`, далее `min f = 2`).

Колонка «prove ∀a» оставлена пустой сознательно: задачи на доказательство
тождеств для всех значений параметра решаются чисто логически, без

### Пустоты

- **По тому, что ищется.** Колонки «число решений» (ЕГЭ-18 — классический
  жанр), «локализация решений», «оптимизация» не покрыты.
- **По структуре.** Строки «система неравенств» и «смешанная система»
  пусты.

### Связь с типологией приёмов

Задачи в пустых колонках («число решений», «локализация», «оптимизация»)
преимущественно требуют постпроцессинговых приёмов (редукция
мета-вопроса, ОДЗ-фильтр) и case-split по порядку выражений — то есть
приёмов, представленных в текущем каталоге минимально (одна-две карточки
на каждый). Сетка постановок и таблица приёмов указывают на одни и те же
области для расширения, что подтверждает направление подбора кандидатов.

## Outline статьи (черновик)

Заголовок (рабочий): «Гибридное решение параметрических задач: координация
логического вывода и детерминированного решателя».

Девять разделов; каждый — короткая аннотация и привязка к материалу выше.

### 1. Введение

Позиционирование. Современные CAS (на примере SymPy) сильны в чистой
алгебраической манипуляции, но систематически теряют решения в
параметрических задачах, требующих координации ветвлений. Rule-based
системы, обратно, плохо масштабируются на алгебру. Параметрические задачи
школьной и абитуриентской алгебры — естественный полигон гибридного
подхода. Опирается на раздел «Тезис».

Отличие от тактического делегирования в proof assistants (Sledgehammer,
`nlinarith`, `polyrith`) — структурное. Их backends (SMT, ATP, Gröbner)
case-split либо делают сами, либо для своих задач не требуют, поэтому
координационный слой в этих системах решает другие задачи (подбор леммы,
реконструкция доказательства). CAS-класс встроенной поддержки
параметрического разбора не имеет; предлагаемая прослойка отвечает на
структурный пробел именно CAS, а целевой артефакт — кусочный ответ по
параметру, не proof-term, — дополнительно отделяет задачу от
proof-assistant-инфраструктуры. Это снимает естественный вопрос
рецензента «не дублирование ли это Sledgehammer-стиля».

### 2. Связанные работы

Тактическое делегирование как архитектурный приём в proof assistants:
`nlinarith` / `omega` в Coq, Sledgehammer в Isabelle, `polyrith` / `ring`
в Lean. Существующие реализации опираются на backends (SMT, ATP, Gröbner,
Positivstellensatz), которые либо делают case-split внутри, либо для
своих задач не требуют; координационный слой поэтому решает другие
проблемы (подбор леммы, реконструкция доказательства из внешней подсказки).
CAS-класс структурно слабее в параметрическом разборе — это и выделяет
нашу прослойку в отдельную нишу. Параметрические задачи
школьно-абитуриентского уровня — класс, не покрытый перечисленными
инструментами из-за несовместимости целевого артефакта (кусочный ответ
vs proof-term).

### 3. Архитектура гибрида

Трёхэтапная схема: логический шаг → делегирование SymPy → сборка ответа.
Каждый компонент описан с эталонным примером. Опирается на раздел «Тезис».

### 4. Семейство логических приёмов

Систематический разбор приёмов по стадии применения: предобработка
(факторизация, знак-разбор модулей, асимптотическая редукция,
распознавание rank-дефицита), case-split (по обнулению, по знаку, по
взаимному порядку выражений), постпроцессинг (ОДЗ-фильтр, редукция
мета-вопроса о разрешимости). Каждый приём — короткое определение,
эталонный пример, сравнение с поведением чистого SymPy. Опирается на
раздел «Семейство гибридных приёмов».

интерпретацией: какие связаны со scope (prove ∀a — вне гибридного фокуса),
а какие — с неполнотой выборки (число решений, локализация, системы
неравенств). Опирается на раздел «Сетка покрытия».

### 7. Реализация в laffie

Архитектурный паттерн: rule-based pattern matching, явное представление
дизъюнкции в ответе, procedural symbol как граница доверия (PyO3-bridge к
SymPy). Подробный разбор одной-двух showcase-карточек из раздела 5 — с
фрагментами `.sym` / `.pbl` кода и пошаговым прохождением гибридного
цикла. Конкретный выбор showcase зависит от этапа реализации
(см. план Phase 1). Ссылка на репозиторий и набор verify-скриптов.

### 8. Ограничения

Где гибрид принципиально не применим: тяжёлые алгоритмы без естественной
редукции (Risch-интегрирование, полный Гребнер без факторизации,
RootOf-арифметика); задачи без алгебраической составляющей (prove через
тождества); экспоненциальный взрыв числа ветвей.

### 9. Заключение

Основной вклад: систематическая таксономия логических приёмов
делегирования для параметрических задач + воспроизводимый каталог из
двенадцати верифицированных кейсов на SymPy 1.14.0 + архитектурный
паттерн реализации в laffie. Дальнейшая работа: расширение каталога в
направлении постпроцессинговых приёмов и систем неравенств; внутренние
эксперименты.
