## Поиск рациональных корней многочлена

### Математическая основа

Теорема о рациональных корнях: если моническый многочлен с целыми коэффициентами
`x^n + ... + d == 0` имеет рациональный корень, то он является делителем свободного
члена `d`.

Для немонического случая `a * x^n + ... + d == 0` рациональные корни имеют вид
`p/q`, где `p` делит `d`, а `q` делит `a`. В реализации поддерживается
монический случай.

### Алгоритм

1. Получить делители свободного члена (включая отрицательные).
2. Подставить каждый кандидат в многочлен.
3. Если подстановка даёт 0 — это корень. Делим многочлен на `(x - u)` и сводим
   задачу к многочлену меньшей степени.

### Правило в Laffie

Обобщённое правило в `symbols/power.sym`:

```
rule {
    attr level(5), goal(find(x, ..));

    F == 0 =>
        (x == u) || (Q == 0);

    is_polynomial(F, x),
    free_term(F, x) == d,
    d != 0,
    u in divisors(d),
    substitute(x == u, F) == 0,
    poly_div(F, x - u) == Q;
}
```

Свободные параметры правила: `F` (связывается из template `F == 0`), `d`, `u`, `Q`
(связываются grounding-ом). Семантика отдельных requirement-ов:

- `is_polynomial(F, x)` — предикат, проверяется после связывания `F` и `x`.
- `free_term(F, x) == d` — `==` с параметром `d` в правой части → связывание
  `d ← -6` (для `F = x^3 - 6x^2 + 11x - 6`). Позиция параметра не важна — `==`
  коммутативный.
- `u in divisors(d)` — генератор: при несвязанном левом аргументе перебирает
  элементы множества.
- `substitute(x == u, F) == 0` — после связывания `u` calculator вычисляет
  подстановку; результат сравнивается с 0 → отбрасывает корни-не-делители.
- `poly_div(F, x - u) == Q` — связывает `Q` частным от деления.

Резолюция `(x == u) || (Q == 0)` после grounding принимает вид
`(x == 1) || (x^2 - 5*x + 6 == 0)` — равенство для найденного корня и редукция
задачи к многочлену меньшей степени.

### Hypothesis и grounding

#### Терминология

| Понятие | В коде | Термин в литературе |
|---------|--------|---------------------|
| Гипотеза со свободными параметрами | `Hypothesis` | non-ground clause [1, 2] |
| Конкретизированная гипотеза | `GroundedHypothesis` | ground instance [1, 2] |
| Конкретизация (Hypothesis → GroundedHypothesis) | `ground()` | instantiation / grounding / означивание [3, 4] |
| Свободные параметры | `free_params` | free variables / свободные переменные [4, 5] |

#### Семантика `in`

Двойственный смысл в зависимости от того, связан ли левый аргумент:

- **Связан** → предикат: проверить принадлежность множеству.
- **Не связан** → генератор: перебрать элементы, связать параметр.

#### Алгоритм grounding

Реализован в `Hypothesis::ground()`:

1. Нормализация requirements (калькуляторы выполняются, `Truth::True` отбрасывается).
2. **Итеративное связывание `==`** (`bind_equality_params`): извлечь
   requirements вида `param == term` или `term == param`. В цикле выбирать те,
   где правая часть не содержит свободных параметров → связать, подставить
   во всю гипотезу, повторить. Оставшиеся возвращаются в requirements.
3. Если всё связано — выдать `GroundedHypothesis`. Иначе:
4. **Cartesian product генераторов** (`extract_generators`): извлечь
   `param in set(...)`. Для каждой комбинации значений подставить и повторить
   шаг 2 (re-bind для оставшихся параметров — например, `Q` после связывания `u`).

#### Пример

`F = x^3 - 6x^2 + 11x - 6`, свободные параметры: `d`, `u`, `Q`.

```
После нормализации:
  is_polynomial(F, x)         → true                    → отбросить
  free_term(F, x) == d        → -6 == d                 → bind d = -6

После подстановки d:
  d != 0                      → -6 != 0 → true          → отбросить
  u in divisors(d)            → u in set(-6, …, 6)      → генератор

Cartesian product, u = 1:
  substitute(x == u, F) == 0  → 0 == 0 → true           → отбросить
  poly_div(F, x - u) == Q     → x^2 - 5x + 6 == Q       → bind Q

Резолюция: (x == 1) || (x^2 - 5x + 6 == 0).
```

Для `u = -6`: `substitute(x == -6, F) → -504`, requirement `-504 == 0` остаётся
и отклоняется как ложный.

### Альтернатива: grounding через find-подзадачу

Текущая реализация связывает параметры локально (итеративно `==` + декартово
произведение генераторов). При наличии нескольких генераторов с
взаимозависимостями (`u in set(1,2,3), v in set(4,5,6), u + v == 7`) это
ограниченно — нет constraint propagation.

Альтернативный подход — формировать `find(free_params)` подзадачу с
requirements в качестве условий и делегировать solver-у. Исследован в ветке
`grounding-via-find-subtask`, требует доработки механизма `is known`. Заметки:
`doc/grounding_via_find_notes.md` в этой ветке.
