# База правил

**База правил** — структура, в которой ядро эффективно ищет правила,
применимые к данному терму. Полный перебор всех правил для каждого
терма был бы неприемлем по производительности, поэтому большая часть
заведомо неприменимых отбрасывается на ранних этапах.

В коде это `RulesEngine` (`solver::rule::rules_engine::RulesEngine`).

## Принципы отсева

База строится на двух наблюдениях:

1. Правило с уровнем `Lᵣ` применяется только к термам уровня
   `Lₜ = Lᵣ` (см. [принцип переключения внимания](work_principle.md#переключение-внимания)).
   Значит, поиск можно ограничить правилами текущего уровня терма.
2. Чтобы шаблон правила сопоставился с термом, **все** функциональные
   символы шаблона должны присутствовать в терме. Это необходимое
   условие унификации.

Из (2) следует более сильное наблюдение: можно выбрать **ключевой
символ** шаблона и индексировать правила по нему. Если этот символ
отсутствует в терме — правило заведомо не сработает. Ключевой символ
правила задаётся в коде (`RuleBuilder::with_func_symbol`), по
умолчанию — специальный псевдо-символ `AnySymbol` (правило не
привязано к конкретному функциональному символу).

## Структура

База — двухуровневое отображение:

```
RulesEngine.all_rules
└── HashMap<Level, HashMap<Symbol, Vec<SharedRule>>>
                 │              │
                 │              └─ ключевой символ шаблона
                 └─ уровень правила
```

Дополнительные поля:

| Поле | Назначение |
|------|------------|
| `id_map: HashMap<String, RuleId>` | Текстовый идентификатор (атрибут `id(...)`) → числовой `RuleId`. |
| `rule_queue: VecDeque<Rule>` | Очередь правил, ожидающих регистрации (см. ниже). |
| `last_id: RuleId` | Счётчик идентификаторов. |
| `max_level: Level` | Максимальный встреченный уровень правила; используется для условия выхода из основного цикла. |

## Регистрация правила

`RulesEngine::register_rule`:

1. Назначить новый `RuleId`.
2. Если у правила есть атрибут `id(<text>)` — записать соответствие в
   `id_map`.
3. Попытаться добавить правило (`add_rule`).
4. Прокрутить очередь — возможно, теперь можно добавить правила,
   которые ранее ждали в `rule_queue`.

`RulesEngine::add_rule`:

- Если все правила, упомянутые в атрибуте `block(<id>)`, уже
  зарегистрированы (присутствуют в `id_map`):
  - резолвить текстовые ссылки в `RuleId`, заполнить поле `Rule::block`;
  - обновить `max_level`;
  - положить правило в `all_rules[level][symbol]`.
- Иначе — отложить в `rule_queue`.

Очередь нужна, чтобы порядок регистрации правил не зависел от порядка
загрузки файлов: правило, которое блокирует ещё не загруженное,
перенесётся, а после загрузки нужного правила автоматически встанет
в базу.

## Алгоритм поиска

`RulesEngine::suggest_rules` принимает `TermFilters` исследуемого
терма и текущую цель задачи и возвращает список применимых правил.

### Шаг 1. Выбор уровня

```
level_rules = all_rules[filters.level]   // HashMap<Symbol, Vec<...>>
```

Если правил данного уровня нет — пустой результат.

### Шаг 2. Выбор по ключевым символам

Кандидатов берём из «ячеек» базы, чьи ключевые символы есть в терме,
плюс правила, привязанные к псевдо-символу `AnySymbol`:

```
candidates = level_rules[AnySymbol] ∪ ⋃ s∈Symbols(t) level_rules[s]
```

### Шаг 3. Фильтрация (`Rule::try_filter`)

Каждый кандидат прогоняется через `try_filter`, который последовательно
проверяет:

- `is_term_suitable`:
  - совпадение уровней (защита от ошибок индексации);
  - правило не находится в `applied_rules` терма (уже пробовали);
  - правило не находится в `blocked_rules` терма (заблокировано
    по атрибуту `block` другого правила, ранее применённого к этому
    же дереву вывода);
  - **полное вхождение символов шаблона**:
    `Symbols(rule.pattern) ⊆ Symbols(t)`.
- `goal_mapping`:
  - если у правила есть атрибут `goal(<pattern>)`, целевой терм
    задачи должен матчиться этим шаблоном;
  - если у правила нет атрибута `goal(...)`, оно неприменимо к
    задачам с целевой установкой `transform(...)` (особый случай;
    для `Transform` обычно требуют явный `goal(transform(...))`).

Прошедшие фильтр правила возвращаются вызывающему. На стороне
`Solver::suggest_rules` к ним добавляются локальные правила
(`local_rules`), построенные из ранее выведенных термов, и для
goal-термов в задачах `prove(...)` берётся подмножество правил с
атрибутом `Equivalence` (равносильные преобразования).

## Псевдокод

```
function suggest_rules(R, filters, goal):
    level_rules ← R.all_rules[filters.level]
    if level_rules is empty: return ∅

    candidates ← level_rules[AnySymbol]
    for s in filters.symbols:
        candidates ← candidates ∪ level_rules[s]

    result ← []
    for r in candidates:
        if r.level ≠ filters.level: continue
        if r.id in filters.applied_rules: continue
        if r.id in filters.blocked_rules: continue
        if not (Symbols(r.pattern) ⊆ filters.symbols): continue
        if not goal_mapping(r, goal): continue
        result.append(r)
    return result
```
