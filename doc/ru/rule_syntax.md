# Синтаксис правил

Правила описывают, как из имеющихся термов получаются новые. Этот
документ описывает только синтаксис — общая роль правил, понятия
«гипотеза», «параметр», «уровень» см. в [terminology.md](terminology.md);
жизненный цикл применения правила — в [work_principle.md](work_principle.md).

## Структура

Новое правило вводится ключевым словом `rule`. В фигурных скобках
описывается его содержимое:

```
rule {
    attr <атрибуты>;

    <шаблон> => <вывод>;       // или <=>

    <ограничение_1>,
    <ограничение_2>,
    ...;
}
```

### Действующая часть

Первая строка тела правила, не выделенная ключевым словом, — это его
действующая часть. Допустимы два варианта:

| Запись | Смысл |
|--------|-------|
| `pattern => resolution;` | Одностороннее преобразование. |
| `pattern <=> resolution;` | Равносильное преобразование: правило может применяться к цели задачи на доказательство, давая альтернативную, равносильную цель (см. [преобразование цели](work_principle.md#преобразование-цели-и-эквивалентные-правила)). |

Форма с `<=>` (а также действующая часть, в которой используется `==`,
если она задаёт равенство термов) автоматически получает атрибут
`Equivalence` в правиле. По возможности предпочитайте именно её — она
расширяет применимость правила.

Любые имена в шаблоне и выводе, не являющиеся функциональными символами
системы, считаются **параметрами** правила (placeholder’ами для
подстановки), а не переменными задачи.

### Ограничения

Все строки после действующей части и до закрывающей `}` считаются
**ограничениями** на параметры правила. Они перечисляются через запятую
и заканчиваются точкой с запятой. Ограничения проверяются в процессе
применения; если хотя бы одно не выполнено для текущей подстановки —
происходит откат к следующей подстановке параметров.

В ограничениях допустимы предикаты: сравнения (`==`, `!=`, `<`, `>`,
`<=`, `>=`), `is known`, `symbolic_eq` (синтаксическое сравнение),
логические операции, а также генераторы вида `<param> in set(…)` и
двунаправленные связывания через `==` (см.
[hypothesis.md](hypothesis.md#семантика-операторов-в-требованиях)).

## Атрибуты

Ключевое слово `attr` позволяет задать атрибуты правила. Атрибуты
перечисляются через запятую.

### Управление приоритетом

`level(<num>)` — целочисленный уровень срабатывания правила (`Lᵣ`).
Правило применяется к терму уровня `Lₜ`, только если `Lᵣ = Lₜ`. Чем
ниже уровень, тем «общеупотребимее» правило: общие приёмы ставят на
0, узкоспециальные — выше. Тип в коде — `Level(u64)`, ограничения на
максимум нет; на практике редко используют значения выше десятка.
Подробнее — [принцип переключения внимания](work_principle.md#переключение-внимания).

`goal(<target>)` — фильтр по целевой установке: правило применяется
только в задачах с подходящей целью. Внутри `<target>` допустим
шаблон с параметрами: `goal(find(x))`, `goal(find(x, ..))`,
`goal(prove(...))`, `goal(transform(...))`. Шаблон цели может также
влиять на унификацию параметров — `x` из шаблона цели и из шаблона
правила связываются.

### Идентификация и блокировки

`id(<text>)` — текстовый идентификатор правила. Используется, чтобы
другие правила могли ссылаться на него в `block(...)`.

`block(<rule_id>)` — после успешного применения данного правила к
терму, правило с идентификатором `<rule_id>` запрещается применять к
**результату**. Полезно для отключения правил, выполняющих обратное
преобразование, и для предотвращения замены переменных, для которых
уже найден ответ.

База правил откладывает регистрацию, если упомянутое в `block(...)`
правило ещё не загружено, и автоматически дорегистрирует, как только
оно появится. Поэтому порядок объявления файлов с правилами не имеет
значения. См. [rule_base.md](rule_base.md#регистрация-правила).

### Замена и нормализация

`replace` — после успешного применения правила исходный терм
помечается флагом `REPLACED` и исключается из множества активных
термов основного цикла. Используется в правилах, дающих
эквивалентную, но более удобную форму, чтобы избежать перебора
промежуточных представлений. См.
[иммутабельность и замена](terminology.md#иммутабельность-и-замена).

`normalize(<level>)` — уровень нормализации, применяемой к **результату**
правила. По умолчанию — максимальный (полный канонический вид).
Понижение уровня нужно, когда результат правила должен сохранить
неканоническую форму, чтобы его смог захватить шаблон другого правила.
Уровни и пример — [normalization.md](normalization.md).

### Генератор шаблонов

Атрибуты `zero(<param>)` и `one(<param>)` — это **генератор**: они
требуют от системы рассмотреть дополнительные шаблоны, в которых
указанный параметр заменён на 0 (для `zero`) или 1 (для `one`).
Это нужно, когда шаблон содержит слагаемое или множитель, который
семантически может отсутствовать.

Например, правило с шаблоном `a*x + b == 0` и атрибутами `one(a),
zero(b)` будет порождено в нескольких вариантах:

- `a*x + b == 0` (исходный),
- `x + b == 0` (`a = 1`),
- `a*x == 0` (`b = 0`),
- `x == 0` (`a = 1, b = 0`).

Все варианты получают одинаковые ограничения и вывод, но шаблоны при
этом нормализуются и каждый отдельно ищется в базе правил. Это даёт
один логически связанный набор случаев в одном описании.

## Примеры

Правило, переносящее ненулевую правую часть в левую:

```
rule {
    attr replace, level(0), goal(find(x)), id(move_left);

    a == b <=> a - b == 0;

    !symbolic_eq(b, 0);
}
```

Замечания:

- `replace` исключает исходный терм после переноса.
- `level(0)` ставит правило на наивысший приоритет.
- `id(move_left)` позволяет другим правилам блокировать перенос (см.
  следующий пример).
- Ограничение `!symbolic_eq(b, 0)` — синтаксическая проверка: `b` не
  является константным нулём (отличается от семантического `b != 0`,
  для которого пришлось бы доказывать ненулевой статус).
- В шаблоне `x` появляется в атрибуте `goal`, но не в самом правиле —
  это значит, что правило применяется к любым задачам на поиск
  значения переменной (с любым именем).

Правило решения квадратного уравнения:

```
rule {
    attr level(4), goal(find(x)), one(a), one(b), zero(c), block(move_left);

    a * x^2 + b * x + c == 0 =>
        (((b^2 - 4*a*c) as D) < 0 && x in empty_set) ||
        (D >= 0 && x in set( (-b+sqrt(D))/(2*a), (-b-sqrt(D))/(2*a) ));

    a != 0,
    c is known;
}
```

Замечания:

- `one(a), one(b), zero(c)` — генератор: правило порождает варианты
  шаблона для случаев `a=1`, `b=1`, `c=0` и их сочетаний; иначе шаблон
  не подошёл бы к терму вида `x^2 + 2x = 0`, где `c` отсутствует.
- `block(move_left)` блокирует перенос для результата, чтобы
  усмотрение ответа не мешало решению.
- В выводе `(b^2 - 4*a*c) as D` — синтаксис локального обозначения:
  параметр `D` появляется в выводе, но не в шаблоне, и связывается
  значением выражения; конкретизация описана в
  [hypothesis.md](hypothesis.md).

Правило рекурсивного раскрытия степени суммы констант:

```
rule {
   attr replace, level(4), goal(transform(x)), normalize(2);

   (a+b)^n <=> (a+b)^(n - 1)*(a + b);

   a is known,
   b is known;
}
```

Замечания:

- `normalize(2)` понижает уровень нормализации результата так, чтобы
  пара `(a+b)^(n-1) * (a + b)` не свернулась обратно в `(a+b)^n` до
  применения правил раскрытия скобок умножения.
