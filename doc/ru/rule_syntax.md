## Синтаксис

Новое правило создается с помощью ключевого слова `rule`, далее в фигурных скобках перечисляются
содержимое правила.

### Поля

Первая строка в теле правила, не выделенная ключевым словом, считается действующей частью правила
и должна иметь вид `pattern => resolution;`(1), либо `pattern <=> resolution;`(2). Отличие между
двумя приведенными записями состоит в том, что переход считается равносильным. Это позволяет применять
правило к цели задачи на доказательство, чтобы получать альтернативную цель, эквивалентрую исходной.
По возможности следует использовать именно форму (2) там, где это возможно.

Последующие строки считаются требованиями правила, перечисленными через запятую и оканчивающиеся
точкой с запятой.

#### attr

Ключевое слово `attr` позволяет задавать атрибуты правила. Далее приводится список доступных
атрибутов:

**level(<num>)** - позволяет задать уровень срабатывания от 0 до 20. Правила с более высоким уровнем
срабатывания рассматриваются системой лишь в том случае, если правила с более низким уровнем не
удалось применить, либо если их применение не дало существенных продвижений в решении задачи.

**goal(<target>)** - фильтрующий атрибут, позволяющий ограничить срабатывание приема лишь целевыми
установками определенного вида.

**id(<id>)** - позволяет задать правилу уникальный идентификатор, чтобы иметь возможность ссылаться
на него из других правил.

**block(<rule_id>)** - позволяет заблокировать применение правила с идентификатором <rule_id> к
результату применения данного правила(полезно в тех случаях, когда необходимо заблокировать правило,
осуществляющее обратное преобразование).

**zero(<param>)** - требует от системы рассмотрения случая, когда параметр равен нулю. Актуально в
случае, когда слагаемое может отсутствовать в терме ввиду равенства нулю. Такие случаи могут
быть отдельно рассмотрены при сопоставлении терма с шаблоном.

**one(<param>)** - требует от системы рассмотрения случая, когда параметр равен единицы. Актуально в
случае, когда множитель может отсутствовать в терме ввиду равенства единицы.

**normalize(<level>)** - позволяет задать уровень нормализации результата. По умолчанию устанавливается
максимальный уровень, который применяет все доступные нормализаторы.

**replace** - означает, что полученный результат применения правила эквивалентен исходному терму и
позволяет в дальнейшем полностью исключить рассмотрение исходного терма для сокращения вычислений.
Как правило применяется при упрощающих преобразованиях.

**subtree** - устаревший аттрибут, нет смысла указывать его в текущей версии системы, но он может
встречаться в старых правилах. Его следует игнорировать и удалять по возможности.

## Примеры

```
// Правило переносит ненулевую правую часть влево.
rule {
    attr replace,level(0),goal(find(x)),id(move_left);

    a == b <=> a - b == 0;

    !symbolic_eq(b, 0);
}
```

```
// Правило решения квадратного уравнения.
rule {
    attr level(4),goal(find(x)),one(a),one(b),zero(c),block(move_left);

    a * x^2 + b * x + c == 0 => 
        (((b^2 - 4*a*c) as D) < 0 && x in empty_set) || 
        (D >= 0 && x in set( (-b+sqrt(D))/(2*a), (-b-sqrt(D))/(2*a) ));

    a != 0,
    c is known;
}
```

```
// Правило рекурсивно разворачивает степень суммы констант.
rule {
    attr replace,level(4),goal(transform(x)),normalize(2);

    (a+b)^n <=> (a+b)^(n - 1)*(a + b);

    a is known,
    b is known;
}
```
