# Подзадачи

Решение задачи часто требует промежуточных шагов, выходящих за рамки её
основной целевой установки: упростить выводимый терм, доказать
вспомогательное утверждение для проверки ограничения правила,
рассмотреть случай. Для этого используется механизм **подзадач**.

**Подзадача** — вспомогательная задача, решаемая независимо ради получения
результата для текущей. Подзадача имеет собственное `Solution` и собственный
основной цикл (тот же, что у внешней задачи; см.
[work_principle.md](work_principle.md)). Внешний код использует только её
`answer()`.

## Типы подзадач

| Тип | Когда вызывается | Что делает |
|-----|------------------|------------|
| `Transform(t)` | На шаге упрощения цикла внешней задачи (если `Goal != Transform`). | Пытается заменить терм на его упрощённую форму. |
| `Prove(c)` | На каждом ограничении гипотезы при применении правила. | Доказывает истинность ограничения в контексте задачи. |
| `Find(x)` | Из правил, описывающих рассмотрение случаев и сборку дизъюнкций. | Не вызывается напрямую ядром, но может быть подзадачей, порождённой правилом. |

В коде вызовы соответствуют методам `Solver::transform` (`solver.rs:440`),
`Solver::prove` (`solver.rs:395`) и общему `Solver::solve_subtask`
(`solver.rs:486`).

## Изоляция контекста

Подзадача решается в собственном `Solution` и поэтому видит только
ограниченный набор условий внешней задачи. В подзадачу попадают:

- все термы из внешнего `Solution` с `inference.is_proven()`,
- кроме помеченных флагом `GOAL` (альтернативные цели не должны
  утечь в подзадачу как условия),
- кроме термов-обёрток `answer(...)` (это форма явной записи ответа,
  не общее условие).

Это даёт два полезных эффекта:

1. Вспомогательные термы, выведенные внутри подзадачи, не загрязняют
   контекст внешней задачи.
2. Удобнее отлаживать: видно, в какой именно подзадаче система
   столкнулась с затруднением.

Сборка подзадачи: `Solver::subtask` (`solver.rs:526`).

## Кэш подзадач

Подзадачи кэшируются по тексту целевого терма:
`SolutionState::cache: HashMap<TermBuf, SharedSolution>`.

Алгоритм входа в подзадачу (`Solver::solve_subtask`):

1. Если в кэше есть запись для целевого терма — вернуть её без
   нового запуска решателя.
2. Иначе сначала **поместить в кэш специальный «незавершённый»
   `Solution`** для этого целевого терма, затем запустить
   полноценное решение.
3. По завершении заменить «незавершённый» вариант на полученный.

«Незавершённый» вариант создаётся как `Solution::new(...)` без статуса
`Answer`. У него `answer()` возвращает `None`, так что любая попытка
рекурсивно решить ту же подзадачу получит «решение не найдено» — это
и есть **обнаружение цикла**: вместо ухода в бесконечную рекурсию
система получает корректный отказ и пробует другой путь.

## Лимит вложенности

Глубина вложенности подзадач ограничена константой
`MAX_SUBTASK_LEVEL = 10` (`solver.rs:20`). Внешняя задача имеет
`subtask_level = 0`; вызов подзадачи увеличивает уровень на единицу
(`Solver::subtask` → `TaskBuilder::with_level`).

Если в `Solver::solve_impl` обнаруживается, что `subtask_level`
превысил лимит, подзадача завершается с ошибкой
`SolveError::MaxSubtaskLevelExceed`. В этом случае запись из кэша
**удаляется** (`solve_subtask`), чтобы повторная попытка с другой
глубины могла пройти.

## Оптимизации `Prove`

`Solver::prove` перед запуском полноценной подзадачи применяет ряд
быстрых проверок, чтобы не платить за лишние циклы:

- **Тривиальная истина.** Цель нормализуется. Если корневой символ
  результата — `is(true)`, обёртка снимается. Если после этого
  `truth().is_true()` — сразу строится «маленькое» решение с
  готовым ответом.
- **Известное от неизвестного.** Если цель имеет вид `t is known`
  и `t` содержит хотя бы одно имя из `unknown_terms` (целей задачи
  `find(x, …)`), цель сразу отвергается с `NoSolutionsFound`. Это
  отсекает попытки доказать «`x` известно» в задачах, где `x` —
  как раз то, что мы ищем.

После этих фильтров вызывается общий `solve_subtask`.

## Особенности `Transform`

`Solver::transform` имеет несколько отличий от других подзадач:

- При входе помечает исходный терм флагом `SIMPLIFIED`, чтобы повторный
  вызов на том же терме был отсечён в основном цикле даже если ответ
  совпал с исходным.
- Если исходный терм имеет вид `answer(t')`, в подзадачу передаётся
  внутренний `t'`, а результат снова оборачивается в `answer(...)` —
  это сохраняет роль терма как явного ответа.
- В результате-новом терме сохраняются `blocked_rules` родителя и
  ставится флаг `SIMPLIFIED`; если родитель был `GOAL`, то и
  результат получает `GOAL`.
- В задачах с целью `Transform` подзадача `Transform` не вызывается
  на шаге упрощения — это излишне, поскольку вся внешняя задача
  и есть преобразование.

## Связанные ошибки

| Ошибка | Когда |
|--------|-------|
| `MaxSubtaskLevelExceed` | Превышен `MAX_SUBTASK_LEVEL`. |
| `NoSolutionsFound` | Подзадача завершилась без ответа. |
| `NoConditions` | В подзадаче нет ни одного активного терма. |
| `ExecutionDeadline` | Лимит итераций (общий для всего вызова `solve`). |
| `Canceled` | Внешняя отмена через `Tracer`. |

Ошибки в подзадаче не означают автоматический провал внешней задачи:
например, отказ в обосновании одного ограничения правила приводит
лишь к отбраковке этой гипотезы и переходу к следующей подстановке.
