# sympy_audit — regression suite каталога

Это воспроизводимый набор скриптов, на которых построены утверждения
«verified на SymPy 1.14.0» в [doc/ru/sympy_catalog.md](../ru/sympy_catalog.md).

## Когда запускать

- **Перед апгрейдом SymPy** — зафиксировать текущий статус каждой
  C-карточки.
- **После апгрейда** — сравнить новый вывод со старым; если поведение
  поменялось, обновить каталог:
  - Карточка перестала воспроизводиться → перенос в секцию «Audit
    обновлений SymPy» с пометкой «работает на N.N.0».
  - Карточка стала проявляться сильнее или появился новый failure-mode →
    обновить тело карточки.
  - Появился новый failure для существующего класса → отдельная новая
    C-карточка.
- **Перед публикацией** — прогнать всю suite и приложить вывод как
  reproducibility appendix.

## Содержимое (committed)

Один скрипт на пачку verified-карточек, имена включают список покрываемых
C-номеров и метод по таксономии:

| Скрипт | Покрывает | Источник |
|---|---|---|
| `verify_C21_C23_so.py` | C21, C22, C23 | StackOverflow |
| `verify_C21_C23_so_round2.py` | то же, расширенные deep-dive проверки + дополнительные SO-кандидаты | StackOverflow |
| `verify_C24_C27_M1.py` | C24, C25, C26, C27 (M1 параметрические) | задачники |
| `verify_C24_C27_M1_round2.py` | расширенные проверки M1, плюс borderline (D3, D4, D5, D6, D7) | задачники |
| `verify_C28_M2.py` | C28 (M2 модули) | задачники |
| `verify_C29_M3.py` | C29 (M3 ОДЗ) | задачники |
| `verify_C30_M4.py` | C30 (M4 тригонометрия) | задачники |
| `verify_M5_audit.py` | M5-пачка (D21, D22, обе в audit) | задачники |
| `verify_C31_olympiad.py` | C31 + олимпиадные/Демидович | задачники |

C1–C20 (исторические карточки) не покрыты автоматическим suite — их
репродьюсеры лежат в `legacy/`. См. backlog ниже.

## Прогон

```bash
# Полный прогон suite на текущей sympy
for f in doc/sympy_audit/verify_*.py; do
    echo "=== $f ==="
    python3 "$f"
done
```

На каждой задаче скрипт печатает:

- ожидаемый ответ (как разобран вручную в комментариях),
- результат `solve` / `solveset` / других sympy-API,
- тёрбл-кейсы (`EXCEPTION: ...`) если sympy бросает.

Diff между прогонами на разных версиях sympy — это и есть сигнал,
требующий ревизии каталога.

## Структура каталогов

```
doc/sympy_audit/
├── README.md               # этот файл
├── verify_*.py             # regression suite (committed)
├── oneshot/                # untracked, см. .gitignore
│   ├── mine_stackexchange.py
│   ├── triage_se.py
│   ├── se_sympy_mine.json  # ~1.5 MB, регенерируется mine_stackexchange.py
│   └── reorder_catalog.py
└── legacy/                 # untracked, см. .gitignore
    ├── sympy_troubles.py
    └── sympy_troubles_more.py
```

- `oneshot/` — скрипты, отработавшие свою задачу: майнинг StackOverflow
  (массово вытащил вопросы), триаж по failure-сигналам, реорганизация
  каталога по тирам. Не нужны в обычном workflow; могут быть удалены или
  перезапущены при расширении выборки.
- `legacy/` — исходные верификаторы для C1–C20 из ранних сессий.
  Сохранены как «оракулы» — сюда подсматривать, если нужно вспомнить,
  как именно каталожная карточка возникла.
